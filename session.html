MODULE 06 · AUTHENTICATION & SECURITY

Session

A server-side record that helps a web application keep track of a user's interaction across requests.

01 · What is it?

A session is temporary state that a server associates with a browser or user across multiple requests.

The browser usually sends a session identifier, while the server keeps the related session data in memory, a database, or a session store.

02 · Think of it like...

A coat-check ticket

Imagine leaving a coat at a coat check. The staff keep the coat; you keep a small ticket that helps them find it later.

A web session works similarly: the server keeps the temporary state, and the browser carries an identifier.

03 · What does it do?

A session lets the server recognize related requests and retain short-lived information while a user interacts with an application.

Keep Login State

Remember that a user has signed in.

Store Temporary Data

Hold a cart, draft, or multi-step form state.

Link Requests

Associate several requests with one interaction.

Expire State

Remove access or data after a timeout or logout.

04 · Where is it used?

Sessions are common wherever a web application needs temporary, user-specific state.

AuthenticationSigned-in websites

Keep a user signed in between page requests.

ShoppingCart state

Remember items while a shopper moves through checkout.

WorkflowsMulti-step forms

Carry progress from one step to the next.

SecurityTemporary controls

Store short-lived state such as a sign-in or verification step.

05 · Example

1. A user submits a login form.

2. The server verifies the password and creates a session record.

3. The server sends a session identifier to the browser.

4. A later request includes that identifier.

5. The server loads the session and applies the user's signed-in state.

A cookie is one common place to carry the session identifier. The session data remains under server-side control.

07 · Do Not Confuse

Session

Temporary state associated with a user or browser across requests.

Cookie

Small browser data that can carry a session identifier to the server.

Authentication

The process of checking who a user is; a session may preserve the result.

Session = server-side continuity; Cookie = one possible browser-side carrier.

09 · What to Remember

A session gives a web application temporary continuity across requests.

The browser usually carries an identifier, while the server controls the session data and its lifetime.
