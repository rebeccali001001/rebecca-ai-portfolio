05 · Embeddings, RAG & Vector Search

What is vector search?

Vector search finds the items closest to a query in embedding space, so retrieval can match intent instead of depending only on exact keywords.

Definition

A vector index stores embeddings and makes nearest-neighbour lookup efficient. At query time, the system embeds the question, retrieves top candidates, and can filter or rerank them.

In plain language

It is a “find the nearest cards” machine for meaning: the closest card is a strong lead, not a final verdict.

Key points

  • Top-k: retrieve a small candidate set rather than the whole library.
  • Hybrid ranking: combine vectors with keywords, metadata, or a reranker.
  • Operational rules: enforce access, freshness, region, and policy-version filters.

Sample: delayed shipment claim

For “What documents are needed for a delayed shipment claim?”, the index returns the closest passages. A metadata filter keeps only the current policy version and the user’s region.

Where it is useful

Knowledge bases, support search, product discovery, similar-case lookup, document triage, and retrieval layers for RAG.

Practical caution

The best value of k is not universal. Too few results can miss evidence; too many can add noise, latency, and context cost.
