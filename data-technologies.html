19 · Product Technology Landscape

Data Technologies

Different data technologies are designed for different kinds of information, access patterns, and application needs.

Start here

Different jobs, different tools

These technologies are not simply competing with one another. Each is optimized for a different way of storing, finding, or using information.

RELATIONAL DATABASE

PostgreSQL

Rich relationships, SQL, and reliable application data.

MySQL

Widely used relational data for web applications.

SQLite

A small, self-contained database inside an application.

DOCUMENT / NOSQL

MongoDB

Documents with a flexible data structure.

CACHE / KEY-VALUE

Redis

Very fast in-memory data access.

VECTOR SEARCH

Vector Databases

Search vector representations for semantic similarity.

01 · Relational databases

Tables, rows, relationships, SQL

Relational databases organize information into tables made of rows and columns. They are a strong fit when data has clear relationships and the application needs reliable, structured queries using SQL.

POSTGRESQL

Flexible, powerful relational database for many kinds of products.

MYSQL

Popular relational database, especially across web applications.

SQLITE

Lightweight relational database stored in a local file.

02 · NoSQL / document

MongoDB

DOCUMENTS

Stores record-shaped data that can feel natural for application objects.

FLEXIBLE STRUCTURE

Useful when records do not all have exactly the same fields or shape.

NoSQL is not automatically better than SQL. The useful question is: what shape does the data have, and how will the product retrieve it?

03 · Fast state

Redis

Redis provides fast in-memory data access. It is commonly used for a cache, sessions, temporary data, queues, or other fast-changing state depending on the architecture.

CACHEKeep frequently used results close at hand.
SESSIONSStore short-lived user or login state.
TEMPORARY DATAHold information that does not need to live forever.
04 · Semantic retrieval

Vector databases

Vector databases store and search vector representations: numerical patterns that capture meaning or similarity. They are useful when a product needs to find things that are semantically similar, not only things with the same exact words.

06 · Remember this

Choose for the product’s access pattern

Different databases are optimized for different jobs, so the right choice depends on how the product needs to store and retrieve data.
