14 · Accessibility

Make the same content and controls usable by more people and input methods.

What is it?

Accessible HTML works with keyboards, screen readers, alternate inputs, and different contexts. Think of it like: clear signs, ramps, and usable controls in a public building.

Native HTML first

<label for="search">Search</label>
<input id="search" type="search">
<button aria-label="Close dialog">×</button>

Common Examples

Write useful image alt text; connect labels with controls; use semantic landmarks; preserve keyboard navigation; use aria-label only when visible text is insufficient; use aria-hidden="true" only for content that should be ignored.

button vs clickable div

button brings keyboard behavior and correct semantics. A div onclick="…" does not. Use native semantic HTML first, then ARIA only to fill a genuine gap.

Common Mistakes

Do not use ARIA to replace broken basic HTML. Do not remove focus outlines without providing a visible replacement.
