Understand the difference between writing a prompt, designing context, setting system-level instructions, and defining output structure.

Prompt Design focuses on how instructions are written. Context Engineering is broader: it decides the complete information environment supplied to the model.

Knowledge Structure
A · INSTRUCTIONS

System Prompts

Application-level instructions that guide behavior.

Prompt Design

How task, constraints, examples, and expected response are communicated.

B · CONTEXT

Context Engineering

Selecting and organizing the information the model receives.

C · OUTPUT CONTRACT

Structured Outputs

Responses constrained to a predictable schema.

One Example

Invoice review in four layers

USER REQUEST

“Check this invoice and return the result.”

SYSTEM PROMPT

You are an invoice review assistant.

PROMPT DESIGN + CONTEXT

Check required fields; include invoice content, validation rules, policy, and prior tool results.

STRUCTURED OUTPUT

{ "status": "...", "issues": [...] }

Key Distinctions
System Prompt≠User PromptApplication instruction vs individual request
Prompt Design≠Context EngineeringWriting the request vs assembling the full environment
Context Engineering≠Context WindowContent selection vs available capacity
Structured Output≠Ordinary proseSchema contract vs free-form response

Remember the structure
Prompt design shapes the request, context engineering shapes what the model can see, system prompts set application-level instructions, and structured outputs define what the application receives.
