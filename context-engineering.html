What Is Context Engineering?

Context Engineering is the practice of deciding what information an AI model should see for a specific task, how that information is organized, and when it should be refreshed.

Prompting is one part of the picture. Context is the whole information environment available during the current model run.

What is it?

Context is everything the model can see for the current request. Context Engineering decides what belongs there.

A prompt is only one input. The full context may combine the System Prompt, Conversation History, User Prompt, Files, Memory, Retrieved Knowledge, Tool Definitions, Tool Results, Agent State, and MCP Tool Schemas.

Think of it like...

LLM = a temporary expert. Prompt = the question you ask. Context = all the materials on the expert's desk.

Context Engineering means deciding which materials belong on the desk, putting them in a useful order, and removing anything distracting, stale, or sensitive.

The best desk is not the desk with the most papers. It is the desk with the right papers for this decision.

The core work is not just writing a better sentence. It is deciding what information enters Context, what stays out, the order it enters, when to retrieve, when to compress, when to compact, and when to delete.

Context Management

Context InjectionAdd useful information to the current context, such as files, retrieved passages, or tool results.
Context CompressionShorten long content while keeping the information needed to complete the task.
Context CompactionTurn older conversation into a shorter working summary when the context is nearly full.
Context ManagementChoose, order, refresh, compress, and remove the information given to the model.
Context WindowThe amount of tokenized information a model can handle in one run.
Why now?Agents use tools, read files, and update state across multiple turns, so the model's visible information keeps changing.

Real-world examples

Customer refund decision

User Request: Can customer 123 receive a refund?

Context: system policy + customer order file + retrieved refund rules + order-status tool result + current case state.

Output: an answer or an approval-needed tool call.

Coding Agent

User Request: Fix the failing checkout test.

Context: system instructions + conversation history + relevant files + test output + tool definitions + agent state.

Output: a patch, a test command, or a request for clarification.

In both examples, adding every document would create noise. The system selects the smallest useful context that supports the next step.

What it is NOT

Context Engineering ≠ Prompt Engineering

Prompt Engineering: improves the wording and structure of an instruction.

Context Engineering: designs the full information environment, including prompt, files, memory, tools, state, and retrieval.

Context Engineering ≠ More Context

Longer context can add noise, stale facts, or sensitive information. Relevance and order matter more than volume.

Context Engineering ≠ Model Training

Context is supplied at runtime. Training or fine-tuning changes learned model parameters.

RAG / Memory / MCP ≠ Context

RAG retrieves knowledge, Memory stores information, and MCP describes a connection pattern. They become part of Context only when their outputs or schemas are supplied to the model.
