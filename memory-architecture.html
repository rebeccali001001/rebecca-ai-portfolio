What is Memory Architecture?

Memory architecture is the system that stores useful information, decides what to retrieve, and places only the relevant part into a model’s current context.

The most important distinction: Memory is not the same as Context. Memory is stored information that may be retrieved later; Context is the information visible to the model for the current run.

What is it?

Memory is information an AI system stores or can retrieve across turns, sessions, or tasks.

A memory system may save a user preference, a fact from a conversation, a past event, or a searchable representation of a document. The model does not automatically see every stored item on every request.

Memory is an application or system capability around the model. It is not proof that the model’s parameters changed.

Think of it like...

Context is the current desk. Memory is the filing cabinet.

The desk holds the documents you are using right now. The filing cabinet holds information that may be useful later. Retrieve Memory means finding the relevant file and putting a useful copy on the desk.

The retrieval step is selective. A system usually brings back the most relevant, permitted, and useful memory—not the entire archive.

Kinds of memory

Working Memory

The information actively used while solving the current task.

Short-Term Memory

Recent information kept for a limited period or current interaction.

Long-Term Memory

Information retained so it can be used across future sessions or tasks.

Conversation Memory

Past messages, summaries, or conversation facts that help maintain continuity.

Semantic Memory

General facts and meanings, such as “the user prefers concise answers.”

Episodic Memory

Specific past events, such as what happened in a previous support case.

User Memory

Information associated with a person, account, or team and used for personalization.

Vector Memory

Stored content or representations that can be found through similarity search.

Four questions to ask

Does the model really “remember”?

Usually, the surrounding application stores and retrieves information. The model receives the selected memory as input for a later run.

Where does memory live?

It may live in a database, application state, conversation store, vector database, files, or a provider-managed memory service.

When is memory retrieved?

Often at request time, before inference. Retrieval can depend on relevance, recency, permissions, task, and user settings.

Why not put everything in context?

Context has finite capacity. Too much information can add cost, slow the system, distract the model, or expose irrelevant and sensitive data.

What it is NOT

Memory ≠ Context

Memory: stored or retrievable information.

Context: information supplied to the current model run.

Memory ≠ Training

Memory: a runtime storage and retrieval capability.

Training: changes model parameters through a learning process.

Memory ≠ Perfect Recall

Memory: depends on what was saved and retrieved.

Perfect recall: is not guaranteed; information may be missing, stale, or wrong.

Memory ≠ Unlimited Context

Memory: helps select useful information.

Unlimited context: is not created by storing more information elsewhere.
