Agent Frameworks

Agent frameworks give developers reusable building blocks for creating AI systems that can use models, tools, state, memory, and multi-step workflows.

On this pageMental modelWhy frameworks existMajor frameworksCategoriesWhat frameworks are notHow to think about choosingQuick comparisonRemember this

Main mental model

MODEL+INSTRUCTIONS+TOOLS+STATE / MEMORY+AGENT LOGIC↓AGENT FRAMEWORK↓AI APPLICATION

Core: A framework helps build the system. Framework is not the model.

Why frameworks exist

WITHOUT A FRAMEWORK

Developers manually manage:

  • tool calls
  • state and agent loops
  • routing and retries
  • multi-agent logic
→
WITH A FRAMEWORK

Reusable orchestration components make common system patterns easier to assemble and maintain.

Simple systems may not need a framework.

Framework categories

GRAPH / STATE ORCHESTRATION

Explicit steps, transitions, and state.

SDK / PROVIDER-NATIVE

Tools and patterns close to a model provider.

MULTI-AGENT

Patterns for several agents to coordinate.

GENERAL AGENT TOOLING

Reusable pieces for building agent applications.

Categories overlap; a framework can fit more than one.

What a framework is not

Framework vs Model

Model: provides AI reasoning and generation capability.

Framework: organizes how models, tools, state, and workflows work together.

Claude / GPT / Gemini models
LangGraph / Agents SDK framework / SDK

Framework vs Agent Product

Framework: used to build AI applications.

Agent product: a ready-to-use experience for users.

LangGraph ≠ Codex
AutoGen ≠ Manus

Framework vs Workflow Platform

Framework: a code-first development layer.

Workflow platform: often visual or low-code orchestration.

LangGraph vs n8n / Dify

There can be overlap between these categories.

How to think about choosing

Need code-level control→ look at a framework or SDK
Need multi-agent patterns→ look at multi-agent-oriented options
Need provider-native integration→ look at a provider SDK
Need visual workflow→ see Module 16
