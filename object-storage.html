MODULE 07 · SYSTEM ARCHITECTURE

Object Storage

Object storage keeps each file-like item as a self-contained object with a key and metadata, making it a strong fit for durable, large-scale storage.

01 · What is it?

Object storage stores content as objects inside buckets or containers, addressed by keys instead of a traditional mounted folder tree.

An object usually includes the bytes, metadata, and a unique key. Applications access it through an API, not by opening a local path.

02 · Think of it like...

Think of object storage like a huge labeled warehouse.

Each package has a label, contents, and description. The label finds the package; it does not imply that the warehouse behaves like a shared office drive.

Application→Bucket→Object Key→Content + Metadata

03 · What does it do?

Durability

Keep large amounts of content available over time.

Scale

Grow capacity without managing a folder server.

Metadata

Attach type, ownership, retention, and application context.

Distribution

Serve content through APIs, signed URLs, or a CDN.

04 · Where is it used?

Backups, analytics exports, images, video, model artifacts, logs, and static assets commonly fit the object model.

05 · Example

A photo product stores an uploaded image under a generated key such as tenant-42/products/sku-81/original.jpg. The product database stores the SKU and object key; the storage service holds the image bytes.

A key can look like a path, but object storage does not automatically provide folder moves, file locks, or POSIX permissions.

06 · How it connects

Client→API→Object Storage→CDN / Download

07 · Do Not Confuse

Object storage

Objects, keys, metadata, and APIs.

File storage

Files, folders, paths, and shared file semantics.

Block storage

Raw volumes formatted by a server or database.

Database

Structured records designed for queries and relationships.

08 · Topic Glossary

See the Module 07 Glossary for the shared bilingual vocabulary.

09 · What to Remember

Object storage is a durable API-accessed content store. It is usually a better fit than file storage for huge scale and immutable or append-oriented content.
