MODULE 07 · SYSTEM ARCHITECTURE

Service

A software unit that provides a specific capability through a defined interface.

01

What is it?

A service is a software unit that provides a specific capability through a defined interface.

The interface tells other parts of the product what they can ask for and what kind of result they can expect. The service keeps the details of how it does the work behind that boundary.

Core definition:
A service is a software unit that provides a specific capability through a defined interface.

Capability

It does a meaningful job, such as pricing an order, sending a notification, or checking inventory.

Interface

It exposes a stable way to request that job, often an API endpoint, function, or message contract.

Boundary

It separates the caller from implementation details, so the inside can change without changing every caller.

02

Think of it like...

Think of a service like a specialist department with a public counter.

A product team does not need to know which employee, database query, or outside provider the department uses. It needs to know what request to make and what result will come back.

Product manager translation

“Who owns this capability, what can other teams ask it to do, and what happens when it is unavailable?”

03

What does it do?

Expose a capability

Give the rest of the system one clear way to request a business operation.

Apply rules

Check decisions such as eligibility, price, inventory, or payment status.

Coordinate work

Call repositories, external APIs, or other services in the right order.

Hide implementation

Keep callers independent from internal storage and provider details.

Return a useful result

Provide success, failure, or a clear status that the caller can act on.

Protect a boundary

Make ownership, permissions, reliability, and change impact easier to reason about.

Trade-off: a service boundary creates clarity and ownership, but it also adds contracts, testing, monitoring, and failure modes. A boundary is useful when the capability is important enough to justify that cost.
04

Where is it used?

Services appear in many architectures. The word describes a responsibility first; it does not automatically mean a separate server or a microservice.

Order and checkout

Validate an order, calculate totals, reserve stock, and create a purchase.

Payments

Authorize a payment and translate a provider response into a product decision.

Notifications

Choose a channel and send email, SMS, or in-app messages.

Identity

Verify credentials, issue sessions, or check access to a protected action.

Search and recommendations

Turn product data into a ranked result for a user or another system.

Internal platform capabilities

Offer shared files, reporting, feature flags, or audit logging through a stable interface.

Synchronous path

The caller waits for a result, such as a price quote or payment decision.

Asynchronous path

Operational path

Logs, metrics, traces, retries, and alerts show whether the capability is healthy and dependable.

07

Do Not Confuse

Service vs component

A component is any bounded part with a responsibility. A service is a component whose responsibility is exposed as a capability for callers.

Service vs API

An API is the interface or contract. A service is the unit that provides the capability behind that interface.

Service vs microservice

A microservice is a service operated as an independently deployable process. A service can also live inside a monolith.

Service vs business logic

Business logic is the rules and decisions. A service is the boundary and coordinator that can contain or call those rules.

09

What to Remember

A service turns one important capability into a clear, reusable boundary.

Its interface is the promise; its implementation can coordinate rules, data, other services, and external systems behind the promise.

PM Perspective

When a team proposes a new service, ask: What capability is being isolated? Who owns the contract? Which users or products depend on it? What latency, failure, data, and operating cost does the boundary introduce?
