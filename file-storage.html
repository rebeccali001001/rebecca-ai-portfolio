MODULE 07 · SYSTEM ARCHITECTURE

File Storage

File storage organizes data as files and folders so people and applications can find, protect, share, and update it through familiar paths.

01 · What is it?

File storage is a way to keep data in files, folders, and directories addressed by paths, with permissions and shares controlling who can use it.

A file has content plus useful metadata such as a name, size, type, owner, timestamps, and location. The storage system exposes file-like operations such as create, read, rename, move, update, and delete.

02 · Think of it like...

Think of file storage like a shared office filing cabinet.

Folders provide a hierarchy, a path tells you where a document lives, and a permission or share decides whether you may view, edit, or pass it on.

03 · What does it do?

File storage gives a product a durable, navigable place for documents and other file-shaped content.

Organize

Group related files into folders, directories, and naming conventions.

Address

Use a path or share link to locate one specific file.

Control access

Apply ownership, permissions, roles, and inherited folder rules.

Share and change

Let people or applications upload, download, rename, edit, and share files.

04 · Where is it used?

Choose file storage when users or existing software need a familiar directory and file interface.

Team documentsShared workspaces

Keep proposals, spreadsheets, contracts, and meeting files in a navigable hierarchy.

Business applicationsAttachments

Store invoices, case evidence, resumes, and customer-uploaded documents beside a business record.

Content workflowsWorking files

Support repeated reads and writes while a team reviews, edits, and publishes media or design files.

Legacy integrationsMounted directories

Connect software that already expects a shared drive, network file system, or POSIX-like path.

05 · Example

A customer-support platform stores evidence uploaded to a case.

/customers/acme/cases/4821/evidence/return-label.pdf
  1. The customer uploads the PDF through the case page.
  2. The file service checks the user’s case permission, scans the file, and writes it to the path.
  3. The application stores the path, size, checksum, and scan result in the database record for case 4821.
  4. An agent receives a time-limited share link instead of broad access to the whole customer folder.

File storage holds the bytes and the directory structure. The database holds searchable business metadata such as case ID, uploader, document type, and review status.

The path is an address, not the business meaning. Products should keep stable IDs and metadata so a rename or move does not break the case record.

A product usually keeps file bytes in file storage and keeps searchable business metadata in a database. Virus scanning, audit logging, versioning, backup, and retention may sit around the file service.

DecisionFile storage helps when...Watch for...
HierarchyUsers need folders, paths, and familiar navigation.Deep or unstable paths can make moves and migrations expensive.
AccessPermissions and shares map to teams and business roles.Inherited permissions and public links need careful review.
ScaleWorkloads have predictable file operations and shared access.Very large namespaces, concurrent edits, or global traffic may need another storage pattern.

07 · Do Not Confuse

File storage

Organizes named files in folders and directories, usually with paths and permissions.

Object storage

Stores self-contained objects in buckets with keys and metadata; it is optimized for durable, large-scale access rather than folder semantics.

Block storage

Provides raw volumes or blocks for a server or database to format and manage; applications do not usually browse its files directly.

Database storage

Stores structured records for querying and relationships. It can store small blobs, but it is not automatically a good home for large files.

The product question is not “Where can bytes go?” It is “What access pattern, ownership model, and scale should the storage system support?”

09 · What to Remember

File storage is the folder-and-path model: it makes files easy to organize, address, permission, and share.

For a PM, define the user’s file workflow first: who uploads, who edits, who shares, how long files remain, and what happens when a file is moved, deleted, or exposed.

PM Perspective

Ask engineering to separate file bytes from business metadata, make access rules explicit, and measure upload success, download latency, scan failures, storage growth, and link or permission incidents.
