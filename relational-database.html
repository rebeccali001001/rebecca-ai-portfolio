MODULE 05 · DATABASE & SQL

Relational Database

A relational database organizes structured data into tables and connects those tables through relationships.

01 · What is it?

A relational database stores structured data in tables and uses shared fields to connect related records across those tables.

Each table usually represents one kind of thing, such as users, orders, or products. Rows hold records, columns describe fields, and keys make connections explicit.

02 · Think of it like…

Think of it like a set of spreadsheets with carefully managed links.

One sheet lists customers, another lists orders, and an order keeps the customer ID that points back to the right customer. The link avoids copying the same customer details into every order.

customers

One row per customer.

id · name · email

orders

One row per order.

id · customer_id · total

03 · What does it do?

A relational database helps software keep structured data consistent and useful.

Organize

Keep related data in clear tables.

Connect

Link records with keys and relationships.

Query

Find combined answers with SQL.

Protect

Enforce rules with constraints and transactions.

04 · Where is it used?

Relational databases are common when an application needs reliable records, clear links, and repeatable queries.

Commerce

Customers, carts, orders, and payments.

Finance

Accounts, transfers, balances, and audit records.

Healthcare

Patients, appointments, clinicians, and results.

Operations

Inventory, suppliers, tickets, and schedules.

07 · Do Not Confuse

Relational Database

The data system

Stores tables and manages relationships, rules, and transactions.

SQL

The language

Expresses queries and data changes for relational databases.

DBMS

The manager

Software that runs and controls database storage, access, and operations.

Table表A structure that stores one kind of data in rows and columns.按行和列保存某一类数据的结构。
Row行One complete record in a table.表中的一条完整记录。

09 · What to Remember

Relational databases organize structured data into tables.

Keys connect related records, and SQL works across those relationships.

Constraints and transactions help keep data reliable as applications change it.
