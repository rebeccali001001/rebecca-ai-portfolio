PART III · HTTP & APIs

PUT

An HTTP method commonly used to replace the current representation of a resource.

01 · What is it?

What is it?

PUT is an HTTP method commonly used to replace an existing resource with the data provided in the request.

Simple Definition: PUT usually sends the full updated version of a resource.

02 · Think of it like...

Think of it like...

Think of a resource as a form.

PUT is like replacing the entire completed form with a new version.

Old Resource→PUT→New Full Version
03 · What does it do?

What does it do?

PUT is commonly used to:

Replace a Resource
Send a Full Updated Record
Update All Main Fields
Save a New Complete Version
04 · Where is it used?

Where is it used?

PUT can be used in APIs that support full resource replacement.

User Profile
Configuration
Product Record
Customer Record
System Resource
05 · Example

Example

Use:

PUT /api/customers/2001

Request Body:

{
  "name": "ABC Trading",
  "status": "Active",
  "country": "Singapore"
}

The request sends the updated representation of customer 2001.

06 · How it connects

How it connects

Client→PUT→Resource Endpoint→Full Resource Data→Backend→Replace Resource→Response

PUT identifies a resource and sends the replacement data for that resource.

07 · Do Not Confuse

Do Not Confuse

PUT

Commonly represents a full replacement or full update.

PATCH

Commonly changes only part of a resource.

PUT = Full Update
PATCH = Partial Update

09 · What to Remember

What to Remember

PUT is commonly used for full resource updates.

PUT sends the new representation of an existing resource.

PUT and PATCH are both update methods, but they are commonly used differently.
