GPU, VRAM, and Unified Memory

AI models need compute to perform calculations and memory to hold model weights and runtime data.

GPU, VRAM, and unified memory describe different parts of that hardware resource picture.

Different architecture, same practical question: does the model have enough compute and memory to run?

GPU

A processor designed for highly parallel computation.

Neural-network inference involves many large matrix operations that GPUs can process efficiently.

GPU = workerThe compute engine doing the calculations.
VRAM = workbenchThe memory available to that worker.

VRAM

Memory directly available to a discrete GPU.

It can hold model weights, KV cache, temporary data, activations, and other inference working data.

Unified Memory

A shared memory pool used by CPU and GPU in a unified-memory architecture.

Apple Silicon is a common example. Instead of separate system RAM and dedicated GPU VRAM, the CPU and GPU can share one memory pool.

Dedicated VRAM

GPU memory is separate from system RAM.

Unified memory

CPU and GPU draw from one shared pool.

A “24 GB unified memory” Mac is not identical to a PC with “24 GB VRAM”.

Why model size is not enough

A model file mainly represents stored model weights. Running the model also needs working memory.

+Model weights+KV cache+Context-related memory+Temporary data+Runtime overhead

A 13 GB model file may require more than 13 GB of memory while running. There is no single fixed multiplier for every model and workload.

One practical example

Computer A

Available: 16 GB VRAM

Model: 13 GB of weights

Question: Does it fit?

Answer: not automatically

Runtime memory is also needed for KV cache, context, temporary data, and overhead.

The model may fit in one workload and fail in another.
