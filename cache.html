MODULE 07 · SYSTEM ARCHITECTURE

Cache

A cache stores reusable data closer to the next request so the system can avoid repeated work.

01 · What is it?

What is it?

A cache is a fast temporary store for data that can be reused.

A cache can reduce latency and load on a database or service, but cached data may become stale and often needs an expiration or invalidation policy.

02 · Think of it like...

Think of it like...

Think of a cache like keeping frequently used documents on your desk instead of walking to a filing room every time.

03 · What does it do?

What does it do?

Reduce latency

Return reusable data from a faster location.

Reduce repeated work

Avoid recomputing or refetching the same result.

Protect the source

Lower repeated reads against a database or service.

04 · Where is it used?

Where is it used?

Request→Cache hit→Fast response

On a cache miss, the system reads from the source, returns the result, and may store it for a later request.

05 · Example

Example

A product page cache can reuse the same catalog response for many shoppers. The product team must decide how quickly price, inventory, and promotion changes need to appear.

06 · How it connects

How it connects

A cache often sits between an application and a slower source such as a database or external API. It works alongside a load balancer, which distributes requests across application instances.

07 · Do Not Confuse

Do Not Confuse

Cache ≠ Database

A cache prioritizes fast reuse; a database is usually the durable source of record.

Cache ≠ Load Balancer

A cache stores reusable results; a load balancer chooses a server for a request.

09 · What to Remember

What to Remember

A cache makes repeated reads faster, but freshness and invalidation are product and system decisions.
