03 · Tokens, Context & Inference

What is latency?

Latency is the time a user waits between sending a request and receiving a response, often split into time to first token and time to completion.

Definition

Latency is elapsed time in a request path: network, queueing, prompt processing, first output, and the rest of generation.

In plain language

It is the wait at the café: how long until someone says “Got it,” and how long until the full drink is ready. Users feel the first wait immediately, even if the final answer is fast to write.

Key points

  • Time to first token (TTFT) describes the first visible response.
  • Time to last token (TTLT) describes total completion time.
  • Long prompts, retrieval, tools, network hops, and queueing can add wait.

Sample: when does the robot answer?

After the order is sent, the useful question is not only “How fast can it write?” but also “How long until it acknowledges the order?”

1 · sendPress the bellThe request leaves the user.
2 · TTFT“Got it”First visible token arrives.
3 · TTLTFull confirmationThe complete answer is ready.

Where it matters

Latency targets shape chat UX, voice interfaces, agents that call tools, interactive coding, and batch workflows. Always report the percentile and the load, not just one best-case number.
