Least Privilege

Least privilege means giving each user, service, or tool only the access it needs for its current task.

01 · What is it?

Least privilege is a security principle that limits access to the smallest set of permissions required to complete an approved task.

Access should be limited by identity, action, resource, and time when those boundaries are useful. Extra access creates extra opportunities for mistakes, misuse, or compromise.

Simple Definition:
Give a caller only the permissions it needs, and no more.

02 · Think of it like...

Think of least privilege like giving a contractor one key for one room during one appointment.

The key opens the room needed for the job.

It does not open every room in the building, and it can be collected when the job is done.

03 · What does it do?

Least privilege puts useful boundaries around what an identity or system component can do.

Reduce Blast Radius

Limit the damage if an account, token, or tool is misused.

Prevent Accidents

Make dangerous or unrelated actions unavailable by default.

Clarify Responsibility

Make it easier to see which identity is allowed to perform an action.

Support Review

Give teams a smaller, clearer permission set to inspect and maintain.

04 · Where is it used?

Least privilege applies anywhere software decides who or what may access a resource.

User AccountsRole and permission design

A person can access the records and actions needed for their job.

Service AccountsBackend integrations

A service can read or change only the data required by its workflow.

APIs and DatabasesScoped access

A caller can use selected endpoints, tables, operations, or fields.

Cloud InfrastructureIdentity and access policies

A workload can reach only the resources it needs to run.

AI Agent ToolsControlled capabilities

An agent can use approved tools without receiving unrestricted system access.

Temporary WorkShort-lived permissions

Access can expire or be removed after a task is complete.

05 · Example

Reporting service
  resource: orders
  actions: read
  fields: id, status, total
  duration: 15 minutes

A reporting service needs to read a small set of order fields. It does not need to create, update, or delete orders, so those permissions are not granted.

If the reporting service is compromised, its limited permissions reduce what the attacker can reach or change.

06 · How it connects

Request→Identity→Policy→Least Privilege Check→Allowed Action→Audit Log

Authentication identifies the caller. Authorization evaluates the policy. Least privilege shapes that policy so the allowed action is as narrow as the task requires.

07 · Do Not Confuse

Authentication

Checks who or what is making a request.

Least privilege: limits what that authenticated caller can do.

Role

Groups a set of responsibilities or permissions.

Least privilege: asks whether that set is still no broader than necessary.

Deny by Default

Blocks access unless a rule allows it.

Least privilege: defines the narrow access that an approved caller receives.

Least privilege does not mean removing all access. It means making access specific, justified, and limited.

09 · What to Remember

Least privilege gives each identity or tool the smallest useful set of permissions for an approved task.

Keep access narrow, review it regularly, and remove or expire it when it is no longer needed.

Core Flow:
Identify the Caller → Check the Policy → Allow Only the Required Action → Record the Result
