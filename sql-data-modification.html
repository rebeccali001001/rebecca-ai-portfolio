01

Querying vs Modifying Data

SELECT reads data. Data modification statements change stored data in a table.

SELECT → reads data
INSERT → adds rows
UPDATE → changes existing rows
DELETE → removes rows

Keep this distinction in mind: Unlike SELECT, data modification statements can affect the database itself.

02

INSERT

INSERT INTO adds a new row to a table.

Example

INSERT INTO sales_orders (
    order_id,
    customer_name,
    metal,
    quantity_mt,
    price_usd,
    status,
    order_date
)
VALUES (
    'SO1004',
    'Eastern Metals',
    'Copper',
    25,
    8550,
    'Pending',
    '2026-09-04'
);

How to read it

  • INSERT INTO → target table
  • column list → fields being populated
  • VALUES → values for the new row

What happens
A new row is added to sales_orders.

03

INSERT Multiple Rows

Place multiple value groups after VALUES to add more than one row in one statement.

INSERT INTO sales_orders (order_id, customer_name, metal, quantity_mt)
VALUES
    ('SO1005', 'North Star Metals', 'Nickel', 18),
    ('SO1006', 'Pacific Alloy', 'Aluminum', 32);

PM takeaway: Each parenthesized group represents one new row, and the values follow the column order.

04

INSERT ... SELECT

INSERT ... SELECT uses the result of a query as the new data.

INSERT INTO archived_orders
SELECT *
FROM sales_orders
WHERE status = 'Completed';

This pattern is useful when copying matching rows into another table. The selected columns must match the destination table's expected structure.

05

UPDATE

UPDATE changes existing rows. SET provides the new value, and WHERE identifies the rows to change.

UPDATE sales_orders
SET status = 'Confirmed'
WHERE order_id = 'SO1002';

How to read it

  • UPDATE → table to change
  • SET → new value
  • WHERE → rows to change

Be careful: Without WHERE, an UPDATE can affect every row in the table.

06

UPDATE Multiple Columns

Separate multiple assignments in the SET clause with commas.

UPDATE sales_orders
SET
    status = 'Confirmed',
    price_usd = 8500
WHERE order_id = 'SO1002';
07

DELETE

DELETE FROM removes matching rows from a table.

DELETE FROM sales_orders
WHERE order_id = 'SO1002';

DELETE removes matching rows.

Be careful: Without WHERE, DELETE can remove every row from the table.

08

Check Before You Change

A common safe workflow is to test the WHERE condition with SELECT before modifying data.

Step 1: Inspect the row

SELECT *
FROM sales_orders
WHERE order_id = 'SO1002';

Step 2: Confirm the rows

Make sure the returned rows are exactly the rows you intend to change or remove.

Step 3: Reuse the same condition

Use the same WHERE condition in your UPDATE or DELETE statement.

09

Putting It Together

A simple modification workflow is: inspect the row, update the row, and query again to verify the result.

SELECT *
FROM sales_orders
WHERE order_id = 'SO1002';

UPDATE sales_orders
SET status = 'Confirmed'
WHERE order_id = 'SO1002';

SELECT *
FROM sales_orders
WHERE order_id = 'SO1002';

PM takeaway: The first query checks the target, the update applies the change, and the final query verifies what is now stored.

11

How to Think About Data Modification

INSERT → Add
UPDATE → Change
DELETE → Remove

WHERE determines which existing rows are affected by UPDATE and DELETE. Treat it as the part of the statement that defines the target.
