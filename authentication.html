MODULE 06 · AUTHENTICATION & SECURITY

Authentication

Authentication is the process of verifying who a user or system is before access is granted.

01 · What is it?

Authentication checks an identity claim against one or more credentials, such as a password, security key, or trusted identity provider.

The result is an answer to “Who is this?” It does not by itself decide which actions that identity may perform.

02 · Think of it like...

Think of authentication like showing identification at a building entrance.

The visitor states who they are, presents a credential, and waits while the entrance system checks it.

A successful check establishes an identity that the rest of the building can use.

03 · What does it do?

Authentication gives a system a trustworthy identity to use in later access decisions.

Verify Identity

Check that a user or service controls the claimed credential.

Establish a Session

Keep the verified identity available across related requests.

Issue a Token

Create a signed or otherwise protected proof for later requests.

Reject Impostors

Stop requests when credentials are missing, invalid, or expired.

04 · Where is it used?

Authentication appears anywhere a system needs to recognize a person, service, or device.

Web ApplicationsAccount sign-in

Users sign in before viewing private pages or personal data.

APIsService identity

Clients prove which application or service is making a request.

Enterprise SystemsSingle sign-on

An identity provider authenticates employees across connected tools.

DevicesMachine identity

A device proves its identity before connecting to a trusted service.

05 · Example

  1. The user submits an email address and password.
  2. The server finds the account and compares a password hash.
  3. If the check succeeds, the server creates a session or token.
  4. Later requests carry that proof so the server can recognize the user.

The password should be checked against a securely stored hash, not stored as readable text. The session or token should also be protected and expire according to the system’s risk.

Authentication succeeds only when the system can verify the presented credential under its current rules.

07 · Do Not Confuse

Authentication

Checks who a user or system is.

Authorization

Checks what that verified identity is allowed to do.

Credential

Is evidence used during authentication, such as a password or security key.

A successful login does not automatically grant access to every resource or action.

09 · What to Remember

Authentication answers “Who are you?” by verifying a user, service, or device.

It creates a trusted identity that later authorization checks can use.
