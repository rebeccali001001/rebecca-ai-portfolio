Background Job

A task that runs outside the immediate request-response flow.

01

What is it?

A background job is work performed separately from the user's immediate request.

It is useful for tasks that take time, run on a schedule, or do not need to block the user.

Simple Definition：
A background job does work without making the user wait for it.

02

Think of it like...

Think of dropping off clothes at a laundry service.

You submit the task. The work continues in the background. You do not stand there waiting for every step.

Request→Create Job→Return Response
Job→Process→Complete
03

What does it do?

Background jobs can handle:

Email Sending

File Processing

Report Generation

Batch Processing

Data Synchronization

Scheduled Tasks

04

Where is it used?

Background jobs are used in:

Backend SystemsCloud ApplicationsData ProcessingIntegrationsNotificationsScheduled Operations
05

Example

Scenario

User requests an export.

Immediate Flow

User→Export Request→Job Created→Response: Processing

Background Flow

Background Job→Generate File→Store File→Notify User
06

How it connects

API Request→Create Background Job→Queue / Worker→Process→Result

The request can finish before the background work is complete.

07

Do Not Confuse

Normal Request Processing

The user waits for the request to complete.

Background Job

The work continues separately after the initial request.

Normal request: complete now.
Background job: continue separately.

09

What to Remember

Background jobs run outside the immediate request-response flow.

They are useful for slow, scheduled, or batch operations.

Queues and workers are commonly used to process background jobs.
