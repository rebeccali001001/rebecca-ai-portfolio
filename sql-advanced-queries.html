06 · Subqueries & Advanced Queries

Learn how SQL nests queries, checks related data, creates reusable temporary results, and performs calculations across groups without collapsing rows.

01

Subquery

A subquery is a SQL query placed inside another SQL query.

Subquery

A subquery lets one query use the result of another query.

SELECT order_id, customer
FROM orders
WHERE customer_id IN (
    SELECT customer_id
    FROM vip_customers
);

First, the inner query returns VIP customer IDs. Then, the outer query returns orders from those customers.

Inner query output

C01
C03

Final output

order_idcustomer
1001ABC Metals
1003ABC Metals
1004Eastern Metals

The inner query runs logically as an input to the outer query.

Scalar Subquery

A scalar subquery returns one value.

SELECT (
    SELECT MAX(price)
    FROM orders
) AS highest_price;

Output: 16000

The inner query returns one value, 16000. The outer SELECT displays that value as highest_price.

Derived Table

A derived table is a subquery used inside FROM.

SELECT x.product, x.total_quantity
FROM (
    SELECT product,
           SUM(quantity) AS total_quantity
    FROM orders
    GROUP BY product
) x;

The inner query creates a temporary result. The outer query reads from that result using the alias x.

Inner result and final output from x

producttotal_quantity
Copper70
Aluminum50
Nickel10
02

EXISTS

EXISTS

EXISTS checks whether a subquery returns at least one row. It returns true when matching data exists.

SELECT o.order_id, o.customer
FROM orders o
WHERE EXISTS (
    SELECT 1
    FROM payments p
    WHERE p.order_id = o.order_id
);

For each order, SQL checks whether a related payment exists.

order_idcustomer
1001ABC Metals
1003ABC Metals
1004Eastern Metals

Orders 1002 and 1005 are excluded because no payment row exists for them.

NOT EXISTS

NOT EXISTS returns rows when the subquery finds no match.

SELECT o.order_id, o.customer
FROM orders o
WHERE NOT EXISTS (
    SELECT 1
    FROM payments p
    WHERE p.order_id = o.order_id
);
order_idcustomer
1002Global Trade
1005Global Trade

EXISTS means related data exists. NOT EXISTS means related data does not exist.

03

Common Table Expression

WITH

WITH starts a Common Table Expression, usually called a CTE. A CTE gives a temporary query result a name.

WITH cte_name AS (
    SELECT ...
)
SELECT *
FROM cte_name;
WITH completed_orders AS (
    SELECT *
    FROM orders
    WHERE amount >= 150000
)
SELECT order_id, customer, amount
FROM completed_orders;

Step 1: create a temporary result called completed_orders. Step 2: query that temporary result.

order_idcustomeramount
1001ABC Metals170000
1003ABC Metals160000
1004Eastern Metals304500

CTE

A CTE is a named temporary result that exists only for the current SQL statement.

WITH product_totals AS (
    SELECT product,
           SUM(quantity) AS total_quantity
    FROM orders
    GROUP BY product
)
SELECT *
FROM product_totals
WHERE total_quantity > 20;
producttotal_quantity
Copper70
Aluminum50

A CTE makes a multi-step query easier to read. It does not normally create a permanent table.

04

Recursive CTE

WITH RECURSIVE

A recursive CTE repeatedly uses its own previous result. It is commonly used for organization structures, category trees, and parent-child relationships.

Sample employees data:

employee_idemployee_namemanager_id
1AliceNULL
2Bob1
3Carol1
4David2
WITH RECURSIVE org AS (
    SELECT employee_id,
           employee_name,
           manager_id,
           1 AS level
    FROM employees
    WHERE manager_id IS NULL

    UNION ALL

    SELECT e.employee_id,
           e.employee_name,
           e.manager_id,
           org.level + 1
    FROM employees e
    JOIN org
      ON e.manager_id = org.employee_id
)
SELECT *
FROM org;
employee_namelevel
Alice1
Bob2
Carol2
David3

The first query finds the starting row. The recursive part finds the next level repeatedly.

Recursive CTE syntax and support can vary by database system.

05

Window Functions

Window functions calculate values across related rows while keeping every original row in the result.

OVER()

OVER defines the set of rows used by a window function.

SELECT order_id,
       amount,
       SUM(amount) OVER() AS total_amount
FROM orders;

Every original row remains, and total_amount shows 886000 on each row.

Unlike GROUP BY, the original rows are not collapsed.

PARTITION BY

PARTITION BY divides rows into groups inside a window calculation.

SELECT
    customer,
    order_id,
    amount,
    SUM(amount) OVER (
        PARTITION BY customer
    ) AS customer_total
FROM orders;
customerorder_idamountcustomer_total
ABC Metals1001170000330000
ABC Metals1003160000330000
Global Trade1002122500251500
Global Trade1005129000251500
Eastern Metals1004304500304500

Each row remains visible. The customer total is repeated for rows in the same customer group.

ORDER BY in a Window

ORDER BY inside OVER defines the sequence used by the window calculation.

SELECT
    order_id,
    amount,
    ROW_NUMBER() OVER (
        ORDER BY amount DESC
    ) AS row_num
FROM orders;

The output ranks the highest amount first: order 1004 is row 1, followed by 1001, 1003, 1005, and 1002.

ROW_NUMBER()

ROW_NUMBER assigns a unique sequential number to each row.

SELECT
    customer,
    order_id,
    amount,
    ROW_NUMBER() OVER (
        PARTITION BY customer
        ORDER BY amount DESC
    ) AS row_num
FROM orders;

For ABC Metals:

1001 | 170000 | 1
1003 | 160000 | 2

The numbering restarts for each customer because of PARTITION BY.

RANK()

RANK assigns ranking numbers and leaves gaps after ties.

SELECT amount,
       RANK() OVER (ORDER BY amount DESC) AS rank_num
FROM order_amounts;

For amounts 200, 200, 150, the ranks are 1, 1, 3.

DENSE_RANK()

DENSE_RANK also gives equal values the same rank but does not leave gaps.

SELECT amount,
       DENSE_RANK() OVER (ORDER BY amount DESC) AS dense_rank_num
FROM order_amounts;

For amounts 200, 200, 150, the dense ranks are 1, 1, 2.

1, 1, 3

DENSE_RANK

1, 1, 2

LAG()

LAG returns a value from a previous row in the window order.

SELECT
    trade_date,
    price,
    LAG(price) OVER (
        ORDER BY trade_date
    ) AS previous_price
FROM trades;
trade_datepriceprevious_price

LEAD()

LEAD returns a value from a following row.

SELECT
    trade_date,
    price,
    LEAD(price) OVER (
        ORDER BY trade_date
    ) AS next_price
FROM trades;
trade_datepricenext_price
2026-09-0185008550
2026-09-0285508600
2026-09-038600NULL

LAG looks backward. LEAD looks forward.

Partitioned Aggregation

Aggregate Over Partition

An aggregate window function calculates totals for a group without reducing the number of rows.

SELECT
    customer,
    order_id,
    amount,
    SUM(amount) OVER (
        PARTITION BY customer
    ) AS customer_total
FROM orders;

Each order remains visible. The grouped total is added as another column.

07

EXISTS vs IN

IN with Subquery

SELECT order_id, customer
FROM orders
WHERE customer_id IN (
    SELECT customer_id
    FROM vip_customers
);

IN compares customer_id against a list returned by the subquery.

EXISTS for Related Data

SELECT o.order_id, o.customer
FROM orders o
WHERE EXISTS (
    SELECT 1
    FROM vip_customers v
    WHERE v.customer_id = o.customer_id
);

EXISTS checks whether a matching row exists.

IN

Compare against returned values.

EXISTS

Check whether a related row exists.

Both can solve similar business problems. Choose the form that makes the query clearest. Do not assume that one form is always faster.

08

GROUP BY vs Window

GROUP BY

SELECT customer,
       SUM(amount) AS total_amount
FROM orders
GROUP BY customer;
customertotal_amount
ABC Metals330000
Global Trade251500
Eastern Metals304500

Several order rows become one row per customer.

Window Function

SELECT
    customer,
    order_id,
    amount,
    SUM(amount) OVER (
        PARTITION BY customer
    ) AS total_amount
FROM orders;

Output keeps all five order rows and repeats the customer total beside each original order.

GROUP BY

Combines rows. One row per group.

Window function

Keeps individual rows. One row per original record.
