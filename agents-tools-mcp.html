09 · AGENTS, TOOLS & MCP

How does a model become an agent that can act?

A model generates responses. An agent can pursue a goal, use tools, observe results, and continue through multiple steps.

MODEL · intelligence+TOOLS · capabilities+AGENT LOOP · coordination=AGENT SYSTEM

THE PROBLEM THIS MODULE SOLVES

USER REQUEST

“Check order 123 and send the customer an update.”

WHY A MODEL ALONE IS NOT ENOUGH

A model can understand the request and draft text. By itself it cannot:

  • query the order system
  • execute an external action
  • track workflow state
  • ask for approval
  • continue a multi-step task

That extra system is the agent layer.

HOW THE AGENT LOOP WORKS

From a goal to a completed task

01 · GOAL

User defines the outcome.

02 · PLAN

Agent chooses the next action.

03 · ACT

Agent requests a tool.

04 · EXECUTE

Application performs the action.

05 · OBSERVE

Tool result comes back.

06 · CONTINUE OR FINISH

Update state, repeat, or ask approval.

KEY DISTINCTIONS

What not to confuse

MODEL vs AGENT

MODELGenerates or reasons.
AGENTUses model + tools + state + loop.

A model can answer. An agent can carry out a task.

TOOL CALLING vs TOOL EXECUTION

CALLINGRequests an action.
EXECUTIONActually performs the action.

Model: get_order_status(“123”). Application: calls the Order API.

STATE vs MEMORY vs CONTEXT

STATECurrent task status.
MEMORYInformation that may persist.

CONTEXT is information visible to the model right now.

MCP vs TOOL

MCPConnection standard.
TOOLActual capability.

MCP can connect an AI app to a file-search tool.

REMEMBER THIS

An agent is a controlled system around a model: it plans, acts through tools, observes results, keeps state, and loops until the goal is complete or a human must decide.
