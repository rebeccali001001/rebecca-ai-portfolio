Review common SQL query patterns, execution structure, symbols, keywords, and database-specific differences.

01 Common Query Order

These clauses form a common query structure. Not every query needs every clause.

SELECT columns
FROM table
JOIN other_table
    ON condition
WHERE condition
GROUP BY columns
HAVING condition
ORDER BY columns
LIMIT 10;
  • SELECTWhat to return
  • FROMSource table
  • JOINCombine related tables
  • ONDefine the join condition
  • WHEREFilter individual rows
  • GROUP BYCreate groups
  • HAVINGFilter grouped results
  • ORDER BYSort the final result
  • LIMITRestrict the result count

Written order vs logical idea

SQL is written in this common order:

SELECTFROMJOINWHEREGROUP BYHAVINGORDER BYLIMIT

For beginners, it can help to think about the data flow as:

FROM / JOIN↓WHERE↓GROUP BY↓HAVING↓SELECT↓ORDER BY↓LIMIT

This is a simplified learning model. Do not present it as a universal database engine implementation detail.

02 Common SELECT Pattern

SELECT
    o.order_id,
    c.customer_name,
    o.product,
    o.quantity,
    o.price,
    o.quantity * o.price AS amount
FROM orders o
LEFT JOIN customers c
    ON o.customer_id = c.customer_id
WHERE o.status = 'Completed'
  AND o.product IN ('Copper', 'Aluminum')
ORDER BY amount DESC;
  • o.order_idOrder ID
  • c.customer_nameCustomer information from another table
  • o.quantity * o.price AS amountCalculated output
  • LEFT JOINRetain orders while adding customer data
  • WHEREKeep Completed orders
  • INAllow Copper or Aluminum
  • ORDER BY amount DESCShow highest amount first
Input dataOrders and customer rows joined by customer_id, with status, product, quantity, and price available.
Output

This is a common business reporting query pattern.

03 Common Aggregation Pattern

SELECT
    product,
    COUNT(*) AS order_count,
    SUM(quantity) AS total_quantity,
    AVG(price) AS avg_price
FROM orders
WHERE status = 'Completed'
GROUP BY product
HAVING SUM(quantity) > 100
ORDER BY total_quantity DESC;
  • COUNT(*)Count orders
  • SUM(quantity)Total quantity
  • AVG(price)Average price
  • WHEREFilter source rows
  • GROUP BYGroup by product
  • HAVINGFilter grouped totals
  • ORDER BYSort aggregate results
Output example
productorder_counttotal_quantityavg_price
Copper41208600
Aluminum31104200

04 Common CTE Pattern

WITH product_totals AS (
    SELECT
        product,
        SUM(quantity) AS total_quantity
    FROM orders
    GROUP BY product
)
SELECT *
FROM product_totals
WHERE total_quantity > 100;
Step 1Build product_totals.
Step 2Query product_totals.
Temporary CTE resultCopper | 120
Aluminum | 75
Nickel | 40
Final outputCopper | 120

A CTE can make multi-step SQL easier to read.

05 Common Window Pattern

SELECT
    customer,
    order_id,
    amount,
    ROW_NUMBER() OVER (
        PARTITION BY customer
        ORDER BY amount DESC
    ) AS row_num
FROM orders;
  • PARTITION BY customerCreate a separate window for each customer
  • ORDER BY amount DESCHighest amount first
  • ROW_NUMBER()Number the rows inside each customer group
Sample output

The original order rows remain visible.

06 Common UPDATE Safety Pattern

SELECT First

Check the target rows before changing data.

SELECT *
FROM orders
WHERE order_id = 1001;

Output: display the row that will be changed.

UPDATE Second

UPDATE orders
SET status = 'Completed'
WHERE order_id = 1001;

Then verify

SELECT *
FROM orders
WHERE order_id = 1001;
BeforePending
AfterCompleted

Check the WHERE condition before UPDATE or DELETE.

09 SQL Dialects

SQL is broadly similar across database systems, but some syntax differs.

PostgreSQL

A widely used open-source relational database.

Examples: LIMIT, ON CONFLICT

MySQL

A widely used open-source relational database.

Examples: LIMIT, ON DUPLICATE KEY UPDATE

SQL Server

Microsoft's relational database system.

Examples: TOP, SELECT INTO

Oracle

An enterprise relational database system.

Example: MERGE

SQLite

A lightweight embedded relational database.

Commonly used for compact local databases.
