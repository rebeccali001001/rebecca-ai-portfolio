Normalization

Normalization organizes relational data so each fact has a clear home and unnecessary duplication is reduced.

01 · What is it?

Normalization organizes relational data to reduce unnecessary duplication and improve consistency.

It gives each fact a clear home and uses relationships to connect related facts without copying the same information everywhere.

02 · Think of it like…

Think of normalization like sorting a kitchen into labeled cupboards instead of keeping every ingredient in every room.

03 · What does it do?

Reduce Duplication

Store one fact in one appropriate place.

Clarify Relationships

Connect tables with keys instead of copying whole records.

Protect Updates

Change a fact once and avoid conflicting copies.

04 · Where is it used?

Normalization is common in transactional systems such as accounts, orders, inventory, billing, and permissions.

05 · Example

A normalized order system stores customer details in a customers table, order details in orders, and the relationship through a customer key.

customers(id, name, email)
orders(id, customer_id)
order_items(order_id, product_id, quantity)

The customer email is stored once, while each order points back to the customer record.

07 · Do Not Confuse

Normalization

How data is organized to reduce duplication.

Indexing

How a database finds data more efficiently.

Denormalization

A deliberate choice to duplicate data for a performance or reporting need.
