What are Structured Outputs?

Structured outputs make an AI response follow a defined shape that software can inspect.

On this pageWhat is it?Think of it like...How it worksReal-world examplesWhat it is NOTRelated conceptsRemember thisVideo

What is it?

A structured output is a model response that follows a defined schema or format.

Instead of relying on prose that a person must interpret, an application can validate required fields, types, and allowed values before using the result.

Think of it like...

Think of it like filling in a form instead of writing a free-form note.

The form makes the expected fields visible. A completed form can still contain a wrong answer, so structure improves handling but does not replace quality checks.

How it works

1 · SchemaDefine the shapeList fields, types, and allowed values.
2 · PromptExplain the taskTell the model what each field should mean.
3 · GenerateReturn structured dataThe model produces an object or another required format.
4 · ValidateCheck the resultSoftware rejects missing, invalid, or unsafe values.
5 · RouteUse or recoverThe system acts, asks for correction, or hands off.

Real-world examples

Everyday example · Packing list

Input: “What should I pack for rain?”

System: Returns {items, weather, confidence}.

Output: A list an app can display.

Business example · Invoice extraction

Input: An invoice image.

System: Extracts fields with required types.

Output: Valid data or an exception for review.

What it is NOT

Structured output ≠ Accurate output

Structured output: Follows a shape.

Accurate output: Contains correct values.

Schema ≠ Business rule

Schema: Describes fields and types.

Business rule: Describes what is allowed in the real process.

JSON ≠ Safety

JSON: One machine-readable format.

Safety: Also needs validation, permissions, and recovery.
