Evaluation

Prove that the workflow works before scaling it.

Definition

Evaluation compares representative scenarios with an agreed quality bar. It includes workflow outcomes, failure cases, latency, cost, safety boundaries, and trace evidence—not only whether an answer sounds fluent.

In plain English

Test the job, not just the words. A polished response is still a failure if the wrong record was updated, the source was missed, or a person was skipped when they should have reviewed it.

Key points

  • Use real scenarios: include common and edge cases.
  • Define success first: agree on assertions and thresholds.
  • Trace the workflow: inspect retrieval, tools, timing, and handoffs.
  • Test recovery: uncertainty should lead to a safe next action.

Application

Use evaluation before launch, after model or prompt changes, and during rollout. A small versioned scorecard supports a clear go, change, or stop decision.

The evidence should be understandable to both the technical team and the workflow owner.

Sample · taste-test the meal

Before serving the lunch counter's new helper to everyone, taste-test the normal order, an allergy case, a missing ingredient, a delayed ticket, and a case that needs manager approval. Check quality, time, safe refusal, and whether the cook can see what happened.
