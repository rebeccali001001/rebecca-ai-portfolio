What is it?

A KV cache stores intermediate attention data from earlier tokens so a model can reuse it during generation.

During autoregressive generation, earlier tokens do not need to be recomputed from scratch for every new token. Caching their key and value states can reduce repeated work, while the cache still consumes memory and grows with context length.

Think of it like...

Think of it like keeping notes from work already done. When you continue the calculation, you reuse the notes instead of recalculating every earlier step.

This is a learning analogy. The real system uses mathematical models and software controls.

How it works

1 · ReadProcess the promptThe model reads the input token sequence.
2 · StoreKeep key and value statesIntermediate attention data is placed in a cache.
3 · GenerateAdd one tokenThe model computes the new token using the cached history.
4 · AppendExtend the cacheThe new token’s states are added for the next step.
5 · BudgetTrack memoryThe cache grows with the active sequence and concurrent requests.

Real-world examples

Everyday example · Continue a story

Input: A paragraph followed by a new sentence

AI / System: Reuses notes about the paragraph

Output: Less repeated work for the next token

Business example · Shared prefix

Input: Many requests with the same long instructions

AI / System: Reuses cached prefix states when supported

Output: Lower repeated compute or faster first response

What it is NOT

KV Cache ≠ Memory

KV Cache: KV cache holds temporary inference state.

Memory: Memory is application or product storage intended to persist or be retrieved.

KV Cache ≠ Context Window

KV Cache: The context window limits usable tokens.

Context Window: The KV cache is an implementation structure used while processing them.

KV Cache ≠ Training

KV Cache: Caching helps inference efficiency.

Training: Training updates model parameters.
