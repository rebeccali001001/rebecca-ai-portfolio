What are Failure Modes?

A failure mode is a recognizable way an AI workflow can produce a wrong, unsafe, incomplete, or unusable result.

On this pageWhat is it?Think of it like...How it worksReal-world examplesWhat it is NOTRelated conceptsRemember thisVideo

What is it?

A failure mode is a specific pattern of failure that can be detected and tested.

Examples include unsupported claims, invalid output, tool errors, context overload, unsafe actions, and missed handoffs. Naming the mode helps a team assign a detector, owner, and safe response.

Think of it like...

Think of a restaurant kitchen keeping a list of ways an order can go wrong: missing ingredient, wrong table, allergy risk, or delayed ticket. Each one needs a different check and response.

How it works

1 · ObserveCollect the resultInspect the answer, tools, timing, and evidence.
2 · CompareFind the mismatchCompare the result with an expected behavior.
3 · ClassifyName the modeChoose a known failure category or record a new one.
4 · RespondApply the guardrailRepair, retry, abstain, or escalate safely.
5 · LearnTrack the patternUse traces and tests to reduce repeat failures.

Real-world examples

Everyday example · Wrong route

Input: “Take me to the station.”

System: Uses an outdated map or wrong destination.

Output: A mismatch detected and route confirmation requested.

Business example · Policy answer

Input: A question about a current exception.

System: Retrieves no supporting evidence.

Output: Abstain or route to review instead of guessing.

What it is NOT

Failure Mode ≠ Random Bad Luck

Failure mode: A repeatable pattern with a signal.

Random bad luck: A vague label that does not guide a fix.

Failure Mode ≠ Model Error Only

Failure mode: Can occur in data, prompts, tools, policy, or runtime.

Model error: One possible source among several.

Failure Mode ≠ Failure Handling

Failure mode: Describes how the workflow failed.

Failure handling: Describes the safe response.

Related concepts

Expected behavior → Observed signal → Failure mode → Recovery or escalation
Functional Tests expose failure modes. Deployment Readiness checks whether the important ones are controlled in real use.
