05 · Embeddings, RAG & Vector Search

What is vector search?

Vector search finds the items closest to a query in embedding space, so retrieval can match intent instead of depending only on exact keywords.

Topic detail

A vector index stores embeddings and makes nearest-neighbour lookup efficient. At query time, the system embeds the question, retrieves top candidates, and can filter or rerank them.

The result is a candidate set for downstream retrieval—not a guarantee that the top match is correct.

Find the nearest useful items, then apply judgment and rules.

Why it matters

A user may ask about a “delayed shipment claim” while the best document uses different wording. Similarity search can surface the relevant policy before keyword, metadata, and reranking checks narrow the result.

Production indexes should enforce access, freshness, region, and policy-version filters.

Sample

For “What documents are needed for a delayed shipment claim?”, the index returns the closest passages. A metadata filter keeps only the current policy version and the user’s region.

Query
delayed shipment claim
Top candidate
0.93 · claim documents
Filter
current region + version

Easy analogy

Imagine asking a librarian for the book most similar to the one you need. The librarian uses the subject, topic, and nearby shelves to bring back a few strong candidates. Vector search does the same with embeddings, then filters and reranks those candidates before another system uses them.

Key takeaway

Vector search finds candidates by semantic closeness. Combine it with metadata, keyword signals, reranking, permissions, and evaluation before treating a result as evidence.
