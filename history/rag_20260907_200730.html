What is RAG?

Retrieval-Augmented Generation (RAG) lets an AI retrieve relevant information before using a language model to generate an answer.

RAG is not a model — it is a system pattern
Learn the ideaWhat is it?Open-book examHow it worksExamplesWhat it is NOTRelatedRememberVideo

01 · The ideaWhat is it?

An LLM only has its trained knowledge plus the context it receives. RAG adds a retrieval step.

The system first finds relevant external information and then places that information into the model’s context before generation.

02 · Make it intuitiveThink of it like...

Think of RAG like taking an open-book exam.

Without RAG, you answer only from what you remember. With RAG, you first look up the relevant page, then answer using that information.

04 · See it in the real worldReal-world examples

Example 1 · HR policy

“How many annual leave days do I receive?”

RAG: Finds the current HR policy.

LLM: Answers using that policy.

Example 2 · Product manual

“How do I reset this device?”

RAG: Retrieves the relevant manual section.

LLM: Turns it into a simple answer.

Example 3 · Internal assistant

“What is the approval process for invoices over $50,000?”

RAG: Searches company documentation.

Output: An answer based on current internal sources.

05 · Clear up the confusionWhat it is NOT

RAG ≠ Fine-tuning

RAG: Retrieves external information at runtime.

Fine-tuning: Changes model behavior through additional training.

RAG ≠ Search Engine

Search Engine: Finds and ranks information.

RAG: Uses retrieved information as context for generation.

RAG ≠ Vector Database

Vector Database: May store and search embeddings.

RAG: The full retrieval + generation workflow.

RAG ≠ Model Knowledge

RAG: Adds external context at runtime.

Model Knowledge: Patterns learned during training.
