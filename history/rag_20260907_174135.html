05 · Embeddings, RAG & Vector Search

What is RAG?

Retrieval-Augmented Generation gives a model relevant evidence from an external knowledge source before it answers.

Topic detail

A RAG system prepares source material, creates an index, retrieves relevant passages at query time, and supplies those passages to a model as context. The answer is then generated from the model plus that retrieved context.

RAG is an application workflow, not a special kind of model training. It is useful when knowledge changes or must remain outside model weights.

Retrieve first, compose context, generate second.

Why it matters

Policies, product catalogs, and internal procedures change. Retrieval lets an application connect a capable general model to a current, scoped source instead of relying only on what the model learned during training.

It also creates a place to attach citations, source IDs, permissions, freshness checks, and abstention behavior.

Sample

An operations assistant retrieves settlement policy v4.2, places the relevant excerpt into context, and cites the policy section before answering a question about an exception.

1 · Index
policy chunks + metadata
2 · Retrieve
current §3.1 passage
3 · Generate
answer + citation

Easy analogy

Think of an open-book exam. The student still needs to understand the question and explain an answer, but the relevant pages are on the desk. RAG is similar: retrieved context gives the model pages to work from, but it can still misread a page or fail when the right page is missing.

Key takeaway

RAG is a workflow: index, retrieve, compose context, generate, and verify. It improves access to evidence but does not remove the need for evaluation.
