What are Functional Tests?

Functional tests check whether an AI feature completes the intended job.

On this pageWhat is it?Think of it like...How it worksReal-world examplesWhat it is NOTRelated conceptsRemember thisVideo

What is it?

Functional tests check whether an AI feature completes the intended job.

They test the whole behavior, not only whether the response sounds plausible. Good tests use representative inputs, explicit assertions, failure cases, and evidence from the workflow.

Think of it like...

Think of testing a vending machine by checking that payment, selection, dispensing, change, and error handling all work—not only that the screen looks good.

How it works

1 · ScenarioChoose a taskUse representative happy paths and edge cases.
2 · InputRun the featureProvide a fixed fixture, prompt, context, or tool state.
3 · AssertCheck the outcomeVerify schema, tool calls, routing, evidence, or end state.
4 · RecordSave evidenceKeep traces, outputs, and failure information.
5 · ImproveFix and rerunUpdate the system and repeat the test set.

Real-world examples

Everyday example · Structured answer

Input: a request with known fields

AI / System: checks required fields and valid types

Output: an accepted or rejected object

Business example · Invoice agent

Input: an invoice fixture

AI / System: checks extraction, refusal, and routing

Output: a correct end state or safe escalation

What it is NOT

Functional Test ≠ Fluency check

functional test: checks the intended workflow outcome

fluency check: checks whether text sounds natural

Test pass ≠ General truth

test pass: evidence for tested cases

general truth: requires broader evaluation and monitoring

Test case ≠ Production user

test case: a controlled scenario

production user: varied, changing, and sometimes unexpected
