What are runtime constraints?

Runtime constraints are the limits around a running model—memory, context, latency, concurrency, thermals, and protocol fit—that determine whether a local system is actually usable.

Definition

A model can load successfully and still fail the real experience. Runtime constraints describe the budget the model shares with the operating system, application, conversation history, tools, and other requests.

In plain language

Think of a small elevator. It can carry the same kind of people, but capacity, waiting time, repeated trips, and heat determine what the building can support.

Key points

  • Memory: weights and KV cache compete for limited space.
  • Latency: time to first token and steady generation shape how responsive it feels.
  • Load: longer context, tool schemas, concurrent users, and thermal limits can change behavior.

Life-like Sample: a local coding agent

A local agent answers a short question quickly. After several tool calls, the context contains instructions, file contents, command output, and history. The KV cache grows, memory headroom shrinks, and generation slows. The system has not necessarily crashed; it has crossed its usable budget.

usable experience = capability − (context load + memory pressure + queueing + thermal slowdown)

Where it is useful

  • Choosing a model for a fixed laptop or edge device
  • Setting context and concurrency limits
  • Designing fallbacks when local inference is overloaded
  • Explaining why a demo does not equal deployment readiness

What to measure

TTFTTime to first token
Steady speedTokens generated per second
StabilityMulti-turn recovery and failures

“It runs” is a smoke test. Measure realistic load before calling it usable.
