The short version

What is it?

Model parameters are stored as numbers. Quantization converts those values into lower-precision representations.

Higher precision stores more detail but uses more memory. Lower precision stores numbers more compactly, which usually means less memory and storage—and sometimes better speed. Some model quality may be lost.

Memory ↓Smaller working footprint
Storage ↓Smaller model files
Speed ↑ sometimesDepends on runtime and hardware
A useful mental model

Think of it like…
image compression

An original high-resolution image has more detail and a larger file. A compressed image is smaller and easier to store or use—but some detail may be lost.

Important: this is only an analogy. Quantization changes numerical precision; it is not ordinary ZIP compression.

Why it matters

Real-world examples

01 · Laptop

A full-precision model may not fit into available memory. A quantized version may fit and run locally.

02 · Model choice

Within the same model family, larger quantization quality usually needs more memory; smaller quantization needs less.

03 · Edge device

Quantization may help a model run on a lower-resource device where the original model would be impractical.

Clear up the confusion

What it is NOT

Quantization ≠ ZIP compression

Quantization: changes the numerical precision used to represent model values.

ZIP: compresses file bytes without conceptually changing numerical precision.

Quantization ≠ fine-tuning

Quantization: changes representation / precision.

Fine-tuning: changes learned behavior through training.

Quantization ≠ smaller architecture

Quantized model: usually keeps the same core architecture.

Smaller model: may have fewer parameters or a different architecture.

Lower precision ≠ always better

Less memory is useful, but quality and compatibility trade-offs may exist.
