What is Tool Calling?

Tool calling lets a model ask an application to run a defined function.

On this pageWhat is it?Think of it like...How it worksReal-world examplesWhat it is NOTRelated conceptsRemember thisVideo

What is it?

Tool calling is a structured way for a model to request an action from software.

The application defines a tool name, input schema, permissions, and result format. The model selects or fills the request; the application decides whether and how to execute it.

Think of it like...

Think of it like an assistant deciding when to use a calculator, browser, database, or another tool.

The assistant can point to the right tool and explain the needed inputs, but the tool still controls the actual operation and its access.

How it works

1 · RequestDescribe the taskThe user asks for something that may need outside data or action.
2 · ChooseSelect a toolThe model proposes a tool and arguments from its schema.
3 · ValidateCheck the callThe application checks types, permissions, and confirmation rules.
4 · ExecuteRun the functionThe tool reads data or performs an allowed action.
5 · ReturnSend back the resultThe model uses the result to answer or choose another step.

Real-world examples

Everyday example · Calculator

Input: “What is 18% of 240?”

System: Calls a calculator with the numbers.

Output: 43.2, with less arithmetic risk.

Business example · Order lookup

Input: “Where is order 4812?”

System: Checks the order database after permission checks.

Output: A current status and next step.

What it is NOT

Tool calling ≠ Tool execution

Tool calling: A structured request to use a function.

Tool execution: The application actually runs it.

Tool calling ≠ Browsing by default

Tool calling: Can request any defined tool.

Browsing: One possible tool with its own limits.

Tool calling ≠ Agent

Tool calling: One model-to-application interaction.

Agent: A larger system that may call tools repeatedly.
