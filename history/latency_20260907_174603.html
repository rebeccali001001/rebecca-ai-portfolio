What is it?

Latency is the time between an input being sent and a response or result being available.

In an AI application, people may care about time to first token, time to complete output, or time until a tool action finishes. Latency includes model work, queueing, network calls, retrieval, and application logic.

Think of it like...

Think of it like waiting at a café. Time to first token is how long until someone acknowledges the order; total latency is how long until the complete drink is ready.

This is a learning analogy. The real system uses mathematical models and software controls.

How it works

1 · SendStart the requestThe client sends input to the model or application.
2 · QueueWait for capacityThe request may wait for a worker, GPU, or network.
3 · ProcessRun the pathTokenization, retrieval, model inference, and tools take time.
4 · StreamReturn early outputThe system may show the first token before the full answer.
5 · FinishComplete the resultThe final token or tool action arrives.

Real-world examples

Everyday example · Voice assistant

Input: A spoken question

AI / System: Records, processes, and starts responding

Output: A quick or slow first acknowledgment

Business example · Document workflow

Input: An invoice and extraction request

AI / System: Runs OCR, model inference, and validation

Output: A completed record within a service target

What it is NOT

Latency ≠ Tokens per Second

Latency: Latency measures waiting time.

Tokens per Second: Tokens per Second measures generation rate after generation starts.

Latency ≠ Quality

Latency: A fast response can still be wrong.

Quality: Quality requires separate evaluation.

Latency ≠ Only model speed

Latency: The full path can include queues, tools, retrieval, and networks.

Only model speed: Model compute is only one contributor.
