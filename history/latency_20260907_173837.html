What is it?

Latency is the time between an input being sent and a result being available.

For generative AI, teams often separate time to first token from the time needed to finish the full response.

Think of it like...

Think of it like waiting at a café. You care when the first drink arrives and also how long the whole order takes.

How it works

A request passes through the application, model, tools, and network. Each part contributes to the observed delay.

1 · RequestSend inputThe user or system submits a request.
2 · QueueWait for capacityThe request may wait for a worker or GPU.
3 · ProcessRun model and toolsInference and external calls take time.
4 · First tokenStart respondingStreaming can show progress before completion.
5 · CompleteFinish outputThe final result arrives after all tokens and steps.

Real-world examples

Everyday example · Chat reply

Input: A short question

System: The service processes it and streams output

Output: First token quickly, full reply later

Business example · Approval check

Input: A document and policy request

System: Model plus retrieval and rules run

Output: A decision draft within a target time

AI product example · Voice assistant

Input: Spoken input

System: Speech, model, and speech output run in sequence

Output: A spoken response

What it is NOT

Latency ≠ Tokens per Second

Latency: Total or first-response time

Tokens per Second: Generation throughput after output begins

Latency ≠ Accuracy

Latency: A speed measure

Accuracy: A quality measure; faster is not always better

Latency ≠ Cost

Latency: Time to result

Cost: Resource or usage spend

Related concepts

Input → Queue → Model / tools → First token → Complete
Latency is an end-to-end user experience measure, not only model compute time.
