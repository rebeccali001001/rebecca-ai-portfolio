What is Grounding?

Grounding ties an AI response to relevant, checkable information.

On this pageWhat is it?Think of it like...How it worksReal-world examplesWhat it is NOTRelated conceptsRemember thisVideo

What is it?

Grounding is the practice of connecting a model’s response to specified evidence, data, or tools.

A grounded system can show where an answer came from, limit the answer to an approved source, or refuse when evidence is missing. RAG is one common way to supply evidence, but grounding is the broader reliability goal.

Think of it like...

Think of it like answering a question with the receipt and policy beside you. You can point to the information used instead of relying only on memory or a guess.

How it works

1 · SourceChoose evidenceDefine which documents, records, or tools are trusted.
2 · RetrieveFind supportSelect information relevant to the request.
3 · ConstrainSet boundariesTell the model how to use the evidence.
4 · GenerateWrite the answerThe response uses the supplied context.
5 · CheckShow or test supportCitations, assertions, or review help assess the result.

Real-world examples

Everyday example · Appliance help

Input: a question about a washing machine

AI / System: uses the official manual

Output: steps tied to the cited page

Business example · Finance policy

Input: an expense exception

AI / System: checks the current policy and record

Output: a cited explanation or human review

What it is NOT

Grounding ≠ Fine-tuning

Grounding: connects a response to evidence at use time.

Fine-tuning: changes model behavior through training.

Grounding ≠ RAG only

RAG: retrieves and supplies documents.

Grounding: can also use tools, records, citations, or constraints.

Citation ≠ Proof

Citation: points to a source.

Proof: still depends on source quality and whether it supports the claim.
