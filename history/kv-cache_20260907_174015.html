What is a KV Cache?

A KV Cache stores intermediate attention values from tokens already processed during generation.

What is it?

A KV Cache stores intermediate attention values from tokens already processed during generation.

When the model generates one token at a time, it can reuse these values instead of recalculating the whole earlier sequence for every new token.

Think of it like...

Think of it like keeping notes from work already finished. When the next step arrives, you reuse the notes instead of doing the same calculations again.

How it works

The prompt is processed once, cached values are kept, and each new token extends the cache.

1 · PromptProcess existing tokensThe model reads the current sequence.
2 · CacheKeep intermediate valuesKey and value tensors are stored for reuse.
3 · New tokenGenerate one stepThe model computes the new token against cached context.
4 · AppendExtend the cacheThe new token's values join the stored sequence.
5 · RepeatContinue generationThe loop reuses the cache until the answer stops.

What it is NOT

KV Cache ≠ Context Window

KV Cache: A performance technique for intermediate values

Context Window: The token budget available to the operation

KV Cache ≠ Long-term memory

KV Cache: Temporary inference state

Long-term memory: Information deliberately stored for later retrieval

KV Cache ≠ Model parameters

KV Cache: Runtime values for the current sequence

Model parameters: Learned values that define model behavior

Related concepts

Prompt tokens → Cached attention state + New token → Updated cache
KV Cache improves reuse during inference. It does not expand the model's context limit.
