What is a KV Cache?

A KV cache stores intermediate attention information so a model can reuse earlier work during generation.

On this pageWhat is it?Think of it like...How it worksReal-world examplesWhat it is NOTRelated conceptsRemember thisVideo

What is it?

A KV cache is a runtime cache of key and value tensors computed for tokens that have already been processed.

During autoregressive generation, the model can reuse these tensors instead of recomputing attention for the same earlier tokens. The cache improves speed, but it uses memory and grows with context length.

Think of it like...

Think of it like keeping notes from work already done. When you continue a long calculation, you reuse the notes instead of starting the same calculation again.

How it works

1 · ReadProcess the promptThe model computes attention information for the input tokens.
2 · CacheStore key and value tensorsThe runtime keeps reusable intermediate results.
3 · GenerateAdd one output tokenThe new token is processed against the cached earlier context.
4 · ReuseContinue without repeatingEarlier attention work is reused for the next token.

Real-world examples

Everyday example · Long reply

Input: a prompt with a long history

AI / System: keeps earlier attention results nearby

Output: faster continuation than full recomputation

AI product example · Chat service

Input: a multi-turn conversation

AI / System: allocates cache memory for active requests

Output: better decode throughput within memory limits

What it is NOT

KV Cache ≠ Context Window

KV Cache: stored intermediate computation for reuse

Context Window: the amount of tokenized information allowed

KV Cache ≠ Long-term Memory

KV Cache: temporary runtime state for an active request

Long-term Memory: data stored for later retrieval

KV Cache ≠ Model Parameters

KV Cache: request-specific tensors

Parameters: learned values shared by the model version
