04 · Prompting & System Design

Structured outputs turn a free-form answer into a usable interface.

Instead of asking for “some JSON,” define fields, types, allowed values, and required evidence. Then validate the result before another system acts on it.

Topic Detail

A structured output contract describes the shape of the response. Depending on the model API, native structured-output or schema modes can constrain generation; a separate validator should still check the parsed value and business rules.

{
  "invoice_id": "string",
  "total": "number",
  "currency": "ISO code",
  "needs_review": "boolean"
}

Why it matters

Downstream code can safely parse a predictable shape, log failures, and route exceptions. This makes an AI step composable with queues, databases, and human review instead of forcing every consumer to interpret prose.

Schema validity means “the shape is acceptable.” It does not prove that the values are true.

Sample

An invoice extraction step returns a machine-checkable object:

{
  "invoice_id": "INV-1042",
  "total": 1280.50,
  "currency": "USD",
  "needs_review": false,
  "evidence": ["page 1, total row"]
}

The pipeline parses the object, validates required fields and numeric ranges, then sends only valid records to accounting. A missing total becomes a review item, not a guess.

Easy Analogy

Structured output is like a labeled form at a clinic.

Every box has a meaning and expected format: date, number, yes/no, or a choice from a list. A filled-in form can be processed faster, but staff still verify that the answers make sense.
