What is Tool Calling?

Tool calling lets a model request a defined function, API, database query, or other external action.

On this pageWhat is it?Think of it like...How it worksReal-world examplesWhat it is NOTRelated conceptsRemember thisVideo

What is it?

Tool calling is the pattern where a model selects a named tool and produces arguments for an application to execute.

The model does not automatically gain the tool’s permissions. The application should validate the arguments, enforce access, execute the action, and return the result to the model or user.

Think of it like...

Think of it like an assistant deciding when to use a calculator, browser, database, or another tool. The assistant can request the tool, but the tool still follows its own rules.

How it works

1 · DescribeRegister the toolThe application defines the name, purpose, inputs, and limits.
2 · ChooseSelect a toolThe model decides whether a tool is useful for the current task.
3 · ValidateCheck arguments and permissionTrusted code verifies the request before execution.
4 · ExecuteRun the toolThe external system returns data or performs an allowed action.
5 · ContinueUse the resultThe model or workflow turns the result into the next step.

Real-world examples

Everyday example · Calculator

Input: “What is 18% of 240?”

AI / System: requests a calculator tool

Output: the calculated value

Business example · Order lookup

Input: a customer asks for delivery status

AI / System: calls an order API after permission checks

Output: the current status or a handoff

What it is NOT

Tool Calling ≠ Function Execution

Tool Calling: a model requests an action with arguments

Function execution: application code validates and runs it

Tool Calling ≠ Agent

Tool Calling: one connection pattern between a model and a tool

Agent: a broader system with goals and a loop

Tool Calling ≠ Permission

Tool Calling: describes a possible action

Permission: controls whether the action is allowed
