AI Request Runtime Map

From User Request to AI Action

A practical map of what can happen when a user sends a request to a modern AI application.

USER REQUEST“Check our refund policy and tell me whether this order qualifies.”
↓
APPLICATION → TOKENIZATIONThe app receives the request and converts text into tokens.
↓
CONTEXT ASSEMBLYSystem Prompt + User Prompt + History + Memory / State + Retrieved Knowledge + Tool Results.
↓
MODEL INFERENCENext-token prediction → Sampling → Generated token → Repeat.
↓
FINAL RESPONSE → APPLICATION UI → USERAnswer, action result, or structured output.

OPTIONAL · RAG / KNOWLEDGE BASE

Knowledge Base: policies, documents, manuals, product data.

Chunking / Index → Embeddings / Search → Retrieval → Reranking → Add relevant chunks to context.

OPTIONAL · AGENT LOOP

Observe → Plan / Decide → Act → Tool → Observe Result → Update State → repeat.

State / Memory can feed useful information back into Context Assembly.

OPTIONAL · TOOL CALLING

The model requests a structured tool call; the application or runtime executes it through MCP / API and returns the result to context.

Tool Calling ≠ Tool Execution · MCP ≠ Agent.

CONTROL · VALIDATION / HUMAN REVIEW

Proposed Action → Permission Check → Validation → Human Approval when required → Execute.

FEEDBACK → NEXT RUN

User Feedback → Conversation History / State → Context Assembly. Feedback in a conversation ≠ immediate model training.

Not every request uses retrieval, tools, memory, or an agent loop.

ONE REQUEST, STEP BY STEP

  1. Request enters the application and becomes tokens.
  2. Context is assembled with relevant policy.
  3. If order information is needed, the model requests a tool.
  4. The application queries the order system and returns the result.
  5. The model combines policy and order information into a response.
  6. A real refund action may require permission or human approval.
DO NOT CONFUSE: Token ≠ Word · Context ≠ Memory · Knowledge Base ≠ RAG · Agent ≠ Model · Human Approval ≠ Every AI Request

The AI system layers

Not every AI system needs every layer.

USER / BUSINESS GOALThe outcome a person or organization wants.
AI PRODUCT / APPLICATIONWhat the user interacts with. Examples: ChatGPT Work, Codex, Manus.
AGENT / WORKFLOW LOGICDecides how tasks are carried out: planning, state, tools, and loops.
PROMPTS / CONTEXT / RAGInformation the model receives, including retrieved knowledge and tool results.
MODELProvides learned intelligence and generation capability: GPT, Claude, Qwen, Gemini.
RUNTIME / APIExecutes or serves the model: Ollama, vLLM, or a cloud model API.
HARDWARE / INFRASTRUCTUREProvides compute and memory: GPU, VRAM, unified memory, or cloud compute.
QwenModel capability
OllamaRuns local models
CodexCoding product / agent
LangGraphAgent framework
n8nWorkflow platform

They appear in the same AI system, but they sit at different layers.
