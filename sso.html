MODULE 06 · AUTHENTICATION & SECURITY

SSO

Single sign-on lets a person authenticate with one trusted identity system and then access multiple connected applications.

01 · What is it?

Single sign-on (SSO) is an authentication pattern in which one identity provider verifies a user and connected applications accept that result.

The user does not need to enter a separate application password every time they open another connected service. Each application still creates or uses its own session after it validates the sign-in result.

02 · Think of it like...

Think of SSO like one trusted front desk that issues a badge accepted by several buildings.

You prove who you are at the front desk once. When you visit another connected building, it checks the trusted badge instead of asking you to repeat the full check.

03 · What does it do?

SSO coordinates the authentication handoff between a user, a central identity provider, and multiple applications.

Centralize Sign-in

Keep the main identity check in one trusted service.

Pass Identity

Tell an application which verified user is requesting access.

Support Policy

Apply shared sign-in rules such as MFA or device checks.

Reduce Repeated Passwords

Give users fewer application-specific passwords to manage.

04 · Where is it used?

SSO is useful when one organization or platform manages access to several related applications.

Workforce AppsCompany tools

Employees use one organization account across email, analytics, and internal systems.

Customer PortalsConnected products

A customer uses one account to reach several products from the same provider.

EducationCampus services

Students and staff access learning, library, and administrative tools through one identity.

Partner AccessExternal organizations

A trusted partner identity can be accepted by a shared business application.

05 · Example

Employee opens the company dashboard

1. The employee opens the dashboard and is redirected to the company identity provider.

2. The identity provider checks the existing sign-in and any required MFA policy.

3. The provider returns a signed result to the dashboard.

The application starts its session

The dashboard validates the result, identifies the employee, and creates an application session.

The user can now use the dashboard without entering a second dashboard password.

SSO removes repeated sign-in steps; it does not remove the need for each application to validate the identity result and enforce its own access rules.

06 · How it connects

User→Application→Identity Provider→Signed Result→Application Session→Authorized Request

The identity provider authenticates the user. The application validates the returned result, establishes its session, and then applies authorization rules such as roles and permissions.

07 · Do Not Confuse

SSO vs OAuth

SSO is the user experience and architecture of signing in once across applications. OAuth is an authorization protocol for delegated access.

SSO vs Password Manager

A password manager fills separate credentials. SSO lets connected applications trust one identity provider.

SSO vs Authorization

SSO helps establish identity. Authorization decides what the identified user may do inside an application.

One sign-in does not automatically grant the same permissions in every connected application.

09 · What to Remember

SSO lets one trusted identity provider authenticate a user for multiple connected applications.

Each application still validates the sign-in result, creates its own session, and decides what the user is allowed to do.
