04 · Joining Tables

Learn how SQL combines related data from multiple tables using keys and different types of joins.

01

Why Do We Need Joins?

A relational database often stores related information in separate tables.

sales_orders.customer_id matches customers.customer_id. A join combines related rows without storing all information in one table.

02

JOIN and ON

JOIN combines tables. ON defines how their rows match.

SELECT columns
FROM left_table
JOIN right_table
  ON left_table.key = right_table.key;

The relationship commonly connects a foreign key to a primary or unique key.

03

INNER JOIN

Keeps only rows that have a match in both tables.

SELECT so.order_id, c.customer_name, so.metal, so.quantity_mt
FROM sales_orders AS so
INNER JOIN customers AS c
  ON so.customer_id = c.customer_id;

When to use it: When unmatched orders or customers should be excluded.

PM takeaway: Both sides must match.

04

LEFT JOIN

Keeps every row from the left table. The left table is written before LEFT JOIN.

SELECT so.order_id, c.customer_name
FROM sales_orders AS so
LEFT JOIN customers AS c
  ON so.customer_id = c.customer_id;

If no customer matches, right-table columns return NULL. Use it when every order must remain visible.

05

RIGHT JOIN

Keeps every row from the right table.

SELECT c.customer_name, so.order_id
FROM sales_orders AS so
RIGHT JOIN customers AS c
  ON so.customer_id = c.customer_id;

Customers without orders remain with NULL order columns. A left join is often easier to read by reversing table order, but right join is valid where supported.

06

FULL OUTER JOIN

FULL JOIN or FULL OUTER JOIN keeps matched rows plus unmatched rows from both sides.

SELECT so.order_id, c.customer_name
FROM sales_orders AS so
FULL OUTER JOIN customers AS c
  ON so.customer_id = c.customer_id;

Missing values from either side appear as NULL. Support varies by database.

07

CROSS JOIN

Returns every possible combination of rows and uses no ON condition.

SELECT c.customer_name, r.region_name
FROM customers AS c
CROSS JOIN regions AS r;

Use it deliberately for complete combinations; the result can grow quickly.

08

SELF JOIN

Joins a table to itself using two aliases.

SELECT e.employee_name, m.employee_name AS manager_name
FROM employees AS e
JOIN employees AS m
  ON e.manager_id = m.employee_id;
09

Table Aliases and Qualified Columns

sales_orders AS so and customers AS c create short names that make joins easier to read. A qualified column uses table_alias.column_name, such as so.customer_id or c.customer_id. Qualification is important when both tables have a column with the same name.

10

Putting It Together

SELECT so.order_id, c.customer_name, c.country, so.metal, so.quantity_mt
FROM sales_orders AS so
LEFT JOIN customers AS c ON so.customer_id = c.customer_id
WHERE so.status = 'Confirmed'
ORDER BY so.order_date DESC;

FROM chooses the source, LEFT JOIN adds customer data, ON matches keys, WHERE filters rows, and ORDER BY sorts the result.
