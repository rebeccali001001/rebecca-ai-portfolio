08 · Database Structure

Learn how SQL creates and changes database structures, defines columns and rules, connects tables, and creates reusable database objects.

01 · CREATE TABLE

Create tables, define columns, and choose the data types and constraints that describe each value.

CREATE TABLE

CREATE TABLE creates a new table in the database.

CREATE TABLE customers (
    customer_id INT PRIMARY KEY,
    customer_name VARCHAR(100) NOT NULL,
    country VARCHAR(50),
    email VARCHAR(100)
);

What it means: create a table named customers with four columns.

customerscustomer_idcustomer_namecountryemail
Business model

A customer record has an identifier, name, country, and email address.

Column Definition

Each column definition usually contains a column name, a data type, and optional constraints.

customer_name VARCHAR(100) NOT NULL
customer_namecolumn name
VARCHAR(100)data type
NOT NULLconstraint

Data Type

A data type tells the database what kind of value a column stores.

price DECIMAL(18,2)

The column stores precise decimal numbers.

02 · Common Data Types

Choose a type that matches the values a column should accept. Exact names and behavior can vary between database systems.

INT

INT stores whole numbers.

quantity INT
1025100

BIGINT

BIGINT stores larger whole numbers.

id BIGINT

DECIMAL(p,s)

DECIMAL stores precise decimal numbers.

price DECIMAL(18,2)

18 is the total number of digits; 2 is the number of digits after the decimal point.

8500.25

NUMERIC(p,s)

NUMERIC is another precise numeric type.

amount NUMERIC(18,2)

FLOAT

FLOAT stores approximate numeric values.

rate FLOAT

Use precise decimal types when exact financial values are important.

VARCHAR(n)

VARCHAR stores variable-length text.

customer VARCHAR(100)

CHAR(n)

CHAR stores fixed-length text.

country CHAR(2)
SGCNJP

TEXT

TEXT stores longer text.

remarks TEXT

DATE

DATE stores a calendar date.

trade_date DATE
2026-09-18

TIME

TIME stores a time value.

trade_time TIME

TIMESTAMP

TIMESTAMP stores date and time information.

created_at TIMESTAMP

BOOLEAN

BOOLEAN stores true / false style values in databases that support it.

is_active BOOLEAN

Exact type names and behavior vary between database systems.

03 · Constraints

Constraints define rules for the data stored in a table.

PRIMARY KEY

A PRIMARY KEY uniquely identifies each row.

order_id INT PRIMARY KEY
  • Values must uniquely identify rows.
  • A table normally has one primary key definition.
  • It is commonly used in relationships.

FOREIGN KEY

A FOREIGN KEY links a column to a key in another table.

FOREIGN KEY (customer_id)
REFERENCES customers(customer_id)

orders.customer_id references customers.customer_id.

REFERENCES

REFERENCES identifies the table and column that a foreign key points to.

REFERENCES customers(customer_id)

NOT NULL

NOT NULL requires a value.

customer_name VARCHAR(100) NOT NULL

A row cannot leave customer_name as NULL.

UNIQUE

UNIQUE prevents duplicate values in a constrained column or key.

email VARCHAR(100) UNIQUE

DEFAULT

DEFAULT provides a value when no value is supplied.

status VARCHAR(20) DEFAULT 'Pending'

If an INSERT does not provide status, the output value is Pending.

CHECK

CHECK requires data to satisfy a condition.

CHECK (quantity > 0)

Quantity must be greater than zero.

04 · ALTER TABLE

ALTER TABLE changes the structure of an existing table.

ALTER TABLE

Use ALTER TABLE as the starting point for structural changes.

ALTER TABLE customers
ADD COLUMN phone VARCHAR(30);

ADD COLUMN

Add a new column to the table.

ALTER TABLE customers
ADD COLUMN phone VARCHAR(30);
Before

customer_id · customer_name · country · email

After

customer_id · customer_name · country · email · phone

DROP COLUMN

Remove a column from the table structure.

ALTER TABLE customers
DROP COLUMN phone;

After the statement, phone is removed from the table structure.

RENAME COLUMN

Change a column name.

ALTER TABLE customers
RENAME COLUMN customer_name TO name;

Exact rename syntax varies between databases.

05 · DROP

DROP removes database objects or parts of their structure.

DROP TABLE

DROP TABLE removes a table object. Its stored rows are also no longer available through that table.

DROP TABLE temp_orders;

DROP is a destructive structural operation.

DROP VIEW

Remove the view definition.

DROP VIEW active_orders;

DROP INDEX

Remove an index.

DROP INDEX idx_orders_status;

Exact DROP INDEX syntax can vary by database.

06 · VIEW

A view stores a query definition that can be queried like a virtual table.

CREATE VIEW

Create a reusable named query.

CREATE VIEW active_orders AS
SELECT order_id,
       customer_id,
       product,
       status
FROM orders
WHERE status = 'Completed';

SELECT FROM View

Read from the view as if it were a table.

SELECT *
FROM active_orders;
Sample output1001 · C01 · Copper · Completed1002 · C02 · Aluminum · Completed
Meaning

The result contains Completed orders exposed by the view.

DROP VIEW

Remove the view definition.

DROP VIEW active_orders;

07 · INDEX

Indexes can help the database find rows more efficiently, depending on the query and the database planner.

CREATE INDEX

Create an index on a column that is often used for lookups or filtering.

CREATE INDEX idx_orders_status
ON orders(status);

The index is created on the status column.

CREATE UNIQUE INDEX

A unique index also enforces uniqueness for the indexed key.

CREATE UNIQUE INDEX idx_customers_email
ON customers(email);

DROP INDEX

Remove an index when it is no longer needed.

DROP INDEX idx_orders_status;

Indexes can improve read performance but use storage and add work to data changes.

10 · Temporary Table

A temporary table stores working data for a limited scope or session.

CREATE TEMP TABLE

Create a temporary table containing Completed orders.

CREATE TEMP TABLE temp_orders AS
SELECT *
FROM orders
WHERE status = 'Completed';

SELECT *
FROM temp_orders;

Temporary table syntax and lifetime vary between databases.
