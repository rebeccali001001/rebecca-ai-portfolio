Validation

Checking whether incoming data follows required rules before it is processed.

01

What is it?

Validation checks whether data is acceptable before the system continues processing it.

Validation checks whether the input is valid.

02

Think of it like...

Think of a security checkpoint.

Before data enters the main process, it must pass the required checks.

Input
→
Validation
→
Valid / Invalid
03

What does it do?

Validation can check:

Required Fields

Is a value present when it must be?

Data Types

Is the value a number, text, boolean, or other expected type?

Allowed Values

Does it match one of the accepted choices?

Number Ranges

Is a number within the permitted limits?

Formats

Does it follow a required pattern, such as an email or date?

Business Constraints

Does it meet a rule required by the system?

04

Where is it used?

Validation is used in:

API Requests

Check data received by an endpoint.

Forms

Give users feedback before submission.

Backend Services

Protect processing from invalid input.

Data Imports

Check rows before they enter the system.

Business Workflows

Confirm each step has acceptable data.

Database Operations

Keep stored data within required rules.

07

Do Not Confuse

Validation

Checks whether data is acceptable.

Business Logic

Decides what the business operation should do.

Validation checks the input.
Business logic decides the action.

What to Remember

Validation checks data before processing.

Invalid input should be rejected clearly.

Validation protects business logic and data quality.
