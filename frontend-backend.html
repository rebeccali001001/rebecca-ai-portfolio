Frontend & Backend

Frontend is the part users interact with, while backend is the part that processes logic, data, and services behind the scenes.

FRONTENDshows the result back to the user

Frontend

Frontend = the user-facing layer.

It is what people see and touch: a website, mobile interface, dashboard, or form. Frontend frameworks help teams organize these visible product experiences.

HTMLCSSJavaScriptReactVueNext.js

These are examples, not a coding lesson. Detailed technologies belong in Module 19.

Backend

Backend = server-side processing / application logic.

It works behind the interface: saving an account, checking permission, retrieving an order, calling an AI model, or processing a payment.

Node.jsPythonFastAPIDjango

Backend frameworks are organized ways to build these behind-the-scenes services.

One simple example

USER CLICKS“Generate Summary”
FRONTENDsends request
BACKEND + AIretrieves document, generates summary
BACKENDreturns result
FRONTENDshows summary

Frontend vs Backend

Visible to user
Frontend: yes, directly visible
Backend: mostly hidden
Main responsibility
Frontend: user experience and interaction
Backend: logic, data, and services
Typical data
Frontend: inputs, screens, displayed results
Backend: accounts, records, permissions, model responses
Typical technologies
Frontend: HTML, CSS, JavaScript, React
Backend: Node.js, Python, FastAPI

What is Full Stack?

Full Stack = working across both frontend and backend layers.

A full-stack product connects the experience users see with the logic and services that make it work. The phrase describes coverage across the system, not a separate kind of product.

Remember this

Frontend handles the user experience, while backend handles the logic and services that make the product work.
