## Do Not Confuse Candidates

- Vector database vs embedding: a vector database is the data system that stores and indexes vectors; an embedding is a numerical representation created from content.
- Vector database vs vector search: a vector database is the system and its stored data/indexes; vector search is the method that compares vectors to find matches.
- Vector database vs RAG: a vector database can provide searchable records; RAG is a broader pattern that retrieves context before generation.
- Vector database vs retrieval: the database is an infrastructure component; retrieval is the act or stage of finding relevant information.
- Vector database vs database record: the database is the system; a record is one stored entry inside it.
- Vector database vs vector index: the database can contain vectors, metadata, references, and indexes; an index is the search-supporting structure.
- Vector vs embedding: a vector is an ordered numerical object; an embedding is a representation produced by an embedding process or model and is often stored as a vector.
- Vector representation vs original content: the vector is a numerical representation; the original content is the document, image, product record, or other source material it refers to.
- Vector vs metadata: a vector represents learned or encoded content; metadata describes the item, its source, ID, or other context.
- Stored vector vs query vector: a stored vector comes from indexed source content; a query vector represents the current user request.
- Query vs query vector: a query is the user’s question or request; a query vector is its numerical representation in a vector space.
- Similarity vs distance: similarity expresses how alike items are; distance expresses how far apart they are, and the direction of a better score depends on the metric.
- Nearby vs relevant: nearby means close under the chosen vector comparison; relevant means useful for the user’s task, which is a broader judgment.
- Mathematical similarity vs human understanding: numerical closeness can be useful without proving complete human-level understanding.
- Semantic similarity vs keyword match: semantic similarity can connect different words with related meaning; keyword matching looks for literal words or phrases.
- Matching record vs correct answer: a matching record is retrieved as relevant; it may still be incomplete, outdated, or not sufficient to answer correctly.
- Source reference vs source content: a reference points to content; the content is the material itself.
- Source metadata vs original content: metadata describes where content came from; it is not the content itself.
- Metadata vs document ID: metadata is a broad set of descriptive fields; a document ID is one identifier within or alongside that metadata.
- Content vs context: content is the stored source material; context is information selected for use in a later task such as answering.
- Retrieval vs generation: retrieval finds existing material; generation produces new output such as an answer.
- Retrieval vs RAG: retrieval is one stage or capability; RAG combines retrieval with generation.
- Embedding model vs vector database: the embedding model creates representations; the vector database stores and searches them.
- Embedding model vs vector: a model is the mechanism that converts content; a vector is the resulting numerical object.
- Document vs document chunk: a document is the larger source; a chunk is a smaller piece selected for retrieval.
- Policy chunk vs leave policy: a policy chunk is a retrieved fragment; the leave policy is the complete policy subject or document.
- Source material vs input query: source material is what the system indexes; the query is what the user asks the system to find.
- Input vs output: input enters the system; output is returned after processing.
- Stored item vs matching record: a stored item is any saved object; a matching record is one selected as related to a query.
- Search result vs source reference: a search result is the returned item or content; a source reference identifies where it came from.
- Vector database vs ordinary alphabetical library: a vector database organizes searchable representations by numerical relationships, not only by names or alphabetic order.
- RAG vs answer: RAG is an application pattern; an answer is one generated output that may use retrieved context.
- Relevant context vs complete context: retrieved context can be useful without containing every fact needed for a reliable answer.
- Efficient search vs accurate search: efficiency concerns time and resources; accuracy or relevance concerns whether the returned records are useful.
- Similarity search vs exact lookup: similarity search returns close representations; exact lookup matches an identifier, literal value, or exact key.
- “Same space” vs physical location: the same vector space is a mathematical comparison space, not a physical storage location.
- Vector database vs RAG system: a vector database may support a RAG system, but a RAG system also includes querying, generation, prompts, and application logic.
- Search method vs data system: a search method describes how matching happens; a data system stores and manages the underlying records and indexes.
- Searchable records vs answer evidence: a record can be searchable without being sufficient evidence for a final answer.
- Nearby words vs nearby meanings: the page’s analogy concerns mathematical or semantic closeness, not merely words that are adjacent in a sentence.
