## Do Not Confuse Candidates

- **Relational database vs relational**：relational database 是具体数据库系统类别；relational 是描述数据组织方式的形容词。
- **SQL vs PostgreSQL**：SQL 是查询和管理关系型数据的语言；PostgreSQL 是使用 SQL 的具体数据库产品。
- **PostgreSQL vs Postgres**：Postgres 通常是 PostgreSQL 的简称，不是另一个独立产品类别。
- **MySQL vs SQLite**：两者都是关系型数据库，但 MySQL 常用于 Web 应用；SQLite 更强调小型、自包含和应用内本地文件。
- **SQLite vs local file**：SQLite 是数据库系统；local file 是它可以使用的本地存储载体或位置。
- **Table vs row vs column**：table 是一组结构化记录；row 通常是一条记录；column 是多条记录共有的一个字段。
- **Relational database vs document database**：关系型数据库主要用表、行、列和关系组织数据；文档数据库主要用文档组织数据。
- **NoSQL vs document database**：NoSQL 是更大的非关系型类别；document database 是 NoSQL 中以文档为中心的一类。
- **Document vs document database**：document 是一条数据单位；document database 是保存这类数据的数据库系统。
- **Flexible structure vs unstructured data**：flexible structure 仍可以有结构，只是不要求所有记录字段完全相同；它不等于没有结构。
- **MongoDB vs NoSQL**：MongoDB 是具体产品；NoSQL 是数据库类别或设计取向。
- **Record-shaped data vs relational row**：record-shaped data 描述像记录一样的数据形状；relational row 是关系表中的具体一行。
- **Cache vs database**：cache 主要为了快速、临时地访问可重建数据；database 通常承担更正式的数据保存和管理职责。
- **Cache vs key-value**：cache 描述用途；key-value 描述数据组织方式；一个缓存可以采用键值结构，但两者不是同一个维度。
- **Key vs value**：key 是查找数据的标识；value 是与 key 对应的实际内容。
- **In-memory vs persistent storage**：in-memory 强调数据放在内存中以便快速访问；persistent storage 强调数据在重启后仍能保留，页面未展开后者。
- **Session vs temporary data**：session 是用户或登录相关的短期状态；temporary data 是更宽泛的临时数据。
- **Queue vs cache**：queue 保存等待处理的任务或项目；cache 保存可快速复用的结果或数据。
- **Fast state vs fast-changing state**：fast state 强调需要快速访问；fast-changing state 强调状态经常变化，可能同时具备两种特征。
- **Vector database vs vector search**：vector database 是保存和搜索向量的数据库系统；vector search 是搜索方式或任务。
- **Vector representation vs vector database**：vector representation 是数据的数值表示；vector database 是存储和检索这种表示的系统。
- **Semantic similarity vs exact words**：semantic similarity 按含义判断相近；exact words 关注字面词语是否相同。
- **Semantic search vs exact-match search**：语义搜索可以找到意思相近但用词不同的内容；精确匹配主要要求字面值或词语一致。
- **Similarity vs relevance**：similarity 表示内容彼此相像的程度；relevance 表示结果对当前查询是否有用，页面只直接使用 similarity 和 related documents。
- **RAG vs vector database**：RAG 是“检索后辅助生成”的应用流程；vector database 是该流程可能使用的存储和搜索组件。
- **RAG vs semantic retrieval**：semantic retrieval 是按含义查找；RAG 还包括把检索结果用于生成的后续步骤。
- **Application data vs application**：application data 是应用使用的数据；application 是使用这些数据的软件产品。
- **Database vs data store**：database 通常有更明确的数据管理能力；data store 是更宽泛的存储系统说法。
- **Data storage vs data retrieval**：storage 是保存数据；retrieval 是把保存的数据找出来。
- **Access pattern vs database model**：access pattern 描述应用如何访问数据；database model 描述数据如何组织，两者共同影响技术选择。
- **Typical role vs universal winner**：typical role 只表示某技术常见的工作；页面明确不主张存在适合所有场景的 universal winner。
- **Technology category vs technology product**：category 是 relational、document、cache 或 vector search 等分类；PostgreSQL、MongoDB、Redis 等是具体产品或技术名称。
- **Not simply competing vs interchangeable**：页面说这些技术不是简单竞争关系；不同技术不应被默认视为可以直接互换。
- **Redis vs cache/key-value category**：Redis 是具体技术产品；cache/key-value 是描述用途和组织方式的类别。
- **Vector Databases vs Vector Database**：Vector Databases 是页面中的复数类别标题和表格名称；Vector Database 可指单个向量数据库概念。
- **Data Technologies vs database technologies**：Data Technologies 范围包括数据库、缓存和向量搜索；database technologies 更集中于数据库本身。
- **Store information vs use information**：store information 是保存；use information 还包括读取、查询和在应用中利用。
- **Very fast vs latency**：very fast 是页面的定性描述；latency 是可量化的等待时间概念，页面没有定义具体数值。
