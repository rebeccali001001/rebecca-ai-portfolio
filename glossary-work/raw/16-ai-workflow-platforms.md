## Potential Missing Concepts

These are glossary-worthy concepts suggested by the topic and by operational statements on the page, but they are not fully defined or named as first-class concepts in the source. Keep them as review candidates rather than silently treating them as page-established facts.

- **workflow execution / runtime:** The runtime that executes nodes, passes values, and manages state.
- **workflow run:** One execution instance of a configured workflow.
- **latency:** Time from input to output; important for comparing visual workflows and tool calls.
- **cost per run:** Model, retrieval, tool, and infrastructure cost associated with one execution.
- **token usage:** Model input/output consumption affecting cost and context limits.
- **success rate:** Share of workflow runs that produce an acceptable result.
- **task completion rate:** Whether the workflow completes the intended user task.
- **groundedness / faithfulness:** Whether an answer is supported by retrieved knowledge.
- **retrieval precision / recall:** Quality of document retrieval for RAG workflows.
- **tool-call success rate:** Whether requested tool actions execute correctly.
- **hallucination rate:** Frequency of unsupported or fabricated model output.
- **evaluation set / eval:** Test cases used to assess workflow quality.
- **observability:** Traces, logs, metrics, and run inspection for a workflow.
- **trace:** A record of the nodes, inputs, outputs, and tool calls in one run.
- **logging:** Captured execution information for debugging and monitoring.
- **versioning:** Keeping and comparing versions of prompts, flows, models, and knowledge.
- **rollback:** Returning a workflow to a prior known-good version.
- **retry:** Repeating a failed node or external call.
- **timeout:** Maximum time allowed for a step or run.
- **rate limit:** Restriction on requests to a model provider, API, or tool.
- **queue:** A waiting mechanism for work that cannot execute immediately.
- **concurrency:** Number of workflow runs or nodes executing at the same time.
- **human-in-the-loop:** A human review or approval step inside a workflow.
- **guardrail:** A policy or check constraining model or tool behavior.
- **content moderation:** Checking generated or submitted content against policy.
- **input validation:** Checking that user or form input has the expected shape and values.
- **structured output:** Model output constrained to a known schema for downstream steps.
- **JSON schema:** A machine-readable structure for validating structured workflow output.
- **model routing:** Selecting among model providers or models based on task, cost, or quality.
- **fallback model:** A secondary model used when the preferred model fails or is unavailable.
- **embedding:** A vector representation commonly used to retrieve relevant knowledge.
- **vector store:** A storage system used for embedding-based retrieval.
- **chunking:** Splitting documents into retrieval-sized passages.
- **reranking:** Reordering retrieved passages by relevance before generation.
- **context window:** The amount of input context a model can process in one call.
- **secrets management:** Secure storage and use of API keys and credentials.
- **role-based access control (RBAC):** Restricting workflow, app, data, and tool access by role.
- **audit log:** A record of changes, access, and workflow actions.
- **webhook:** An HTTP callback that triggers or receives workflow events.
- **deployment:** Making a workflow or app available in a target environment.
- **environment:** A development, staging, or production context for a workflow.
- **self-hosting:** Running the platform or workflow infrastructure under the operator’s control.
- **multimodal workflow:** A workflow that handles text plus images, audio, video, or other modalities.
- **human approval:** An explicit approval gate before a consequential action.

## Do Not Confuse Candidates

| Candidate A | Candidate B | Distinction to preserve |
|---|---|---|
| AI workflow platform | Agent framework | The former is often visual / low-code; the latter is typically code-first and exposes primitives and control for custom agent behavior. |
| AI workflow platform | Automation platform | The former is AI-centered around models, prompts, RAG, agents, and tools; the latter is app/business-centered around triggers and business systems. |
| workflow | automation | A workflow is a general ordered flow; automation usually emphasizes event-triggered business or application actions. |
| flow | workflow | “Flow” is the page’s short visual-builder term; it can be broader and less specific than a complete workflow. |
| RAG | knowledge | RAG is a retrieval-and-generation mechanism; knowledge is the source or capability brought into the flow. |
| RAG | retriever | RAG is the end-to-end pattern; a retriever is one component that fetches relevant data. |
| knowledge source | document | A knowledge source can contain documents or other sources; a document is one source item or format. |
| model | model provider | A model is the inference component; a model provider exposes one or more models. |
| prompt | model | A prompt instructs or frames the model; it is not the model itself. |
| tool | API | A tool is a callable workflow capability; an API is an interface through which a service may be called or exposed. |
