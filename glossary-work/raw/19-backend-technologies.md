## Do Not Confuse Candidates

- **Backend vs frontend**：backend 主要在服务端处理逻辑、数据和服务通信；frontend 主要是用户直接看到和操作的部分。
- **Backend vs application**：backend 是应用的一部分；application 是可以包含前端和后端的完整软件。
- **Backend vs backend technology**：backend 是系统中的一部分；backend technology 是用来实现这一部分的语言、运行时或框架。
- **Backend vs backend platform**：backend 是具体应用的服务端实现；backend platform 是为多个应用提供后端能力的平台。

- **Communication vs integration**：communication 强调信息交换；integration 强调把组件连接起来协同工作。
- **Service communication vs API**：service communication 是更广的系统间通信；API 是实现这种调用的一种接口方式。

- **TypeScript vs Node.js**：TypeScript 是语言；Node.js 是运行时，二者位于不同层。
- **Python vs FastAPI**：Python 是编程语言；FastAPI 是使用 Python 的 Web/API 框架。
- **Python vs Django**：Python 是编程语言；Django 是建立在 Python 之上的结构化 Web 框架。
- **Python vs Flask**：Python 是语言；Flask 是使用 Python 的小型、灵活框架。
- **Node.js vs Express**：Node.js 是 JavaScript runtime；Express 是运行在 Node.js 上的 Web framework。
- **Node.js vs NestJS**：Node.js 是运行时；NestJS 是在 Node.js 上组织 TypeScript 服务的框架。

- **Framework vs library**：framework 通常规定或组织应用结构；library 通常被应用主动调用来获得某项能力，页面没有展开这一差异。

- **Structured vs opinionated**：structured 强调有组织；opinionated 强调框架对组织方式有明确偏好，两者相关但不完全同义。
- **Batteries-included vs integrated**：batteries-included 强调内置很多常见能力；integrated 强调能力被整合在一个系统中。
- **Minimal vs small**：minimal 强调功能或内置结构少；small 强调规模或范围小。
- **Flexible vs unstructured**：flexible 不等于没有结构；它表示允许更多选择，框架仍可能提供基本结构。
- **Opinionated vs high structure**：opinionated 描述设计偏好；high structure 描述结构约束程度，常相关但不是同一维度。
- **Moderate structure vs low structure**：moderate 仍提供一定组织方式；low 把更多决定留给开发者。
- **High structure vs complete web application**：high structure 是框架组织程度；complete web application 是应用范围，不能混为一谈。
- **Typical use vs requirement**：typical use 是常见场景；requirement 是具体项目必须满足的条件。
- **Small app vs minimal framework**：small app 是应用规模；minimal framework 是框架自身的设计风格。
- **Large TypeScript service vs NestJS**：large TypeScript service 是使用场景；NestJS 是可用于该场景的框架，不是场景本身。
- **APIs and services vs full web applications**：前者偏向接口和服务；后者是功能更完整的 Web 产品。

- **Routing layer for Node vs Express**：routing layer for Node 是对 Express 的简化理解；Express 还提供其他框架能力，不能只等同于路由。

- **Service layer vs application layer**：service layer 强调可复用服务能力；application layer 强调具体应用行为，边界取决于架构。
