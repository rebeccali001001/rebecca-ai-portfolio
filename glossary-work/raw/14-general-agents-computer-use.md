## Do Not Confuse Candidates

- **Assistant vs Agent**：assistant 主要响应请求；agent 可以使用工具和动作完成多步骤目标。两者是有用的心智模型，不是绝对互斥的产品分类。
- **Agent vs AI product**：agent 是行为或系统模式；AI product 是包含界面、权限、工具和运营的完整应用。
- **Computer Use vs product**：Computer Use 是一种交互能力，不是固定公司、固定应用或单一产品类别。
- **Computer Use vs Tool Calling**：Computer Use 通过图形界面看屏幕、点击和输入；Tool Calling 通过结构化软件接口或工具执行操作。
- **Computer Use vs Browser Agent**：Computer Use 是更广的能力；Browser Agent 是主要在网页和浏览器中工作的智能体，可能使用 Computer Use。
- **Computer Use vs Desktop Agent**：Desktop Agent 是工作在本地桌面软件中的 agent；Computer Use 可以支持桌面，也可以支持浏览器环境。
- **Browser Agent vs Desktop Agent**：Browser Agent 重点是网站和浏览器；Desktop Agent 重点是本地软件和图形界面，权限和运行环境不同。
- **Browser vs website**：browser 是访问网页的软件；website 是被访问的网页服务或页面集合。
- **Desktop vs desktop software**：desktop 是运行环境；desktop software 是运行在其中的应用程序。
- **GUI vs API**：GUI 通过视觉控件交互；API 通过结构化程序接口交互。
- **Structured interface vs graphical interface**：前者有预定义参数和返回值；后者依赖屏幕状态和可见控件。
- **Tool vs tool calling**：tool 是可被使用的外部能力；tool calling 是调用该能力的机制或动作。
- **Action vs capability**：capability 是“能做什么”；action 是实际执行的一次操作。
- **Plan vs workflow**：plan 是为当前目标安排的步骤；workflow 是按顺序组织起来的流程，可能预先固定或由 agent 动态形成。
- **Observe vs validate**：observe 是查看发生了什么；validate 是判断输入、输出或状态变化是否符合要求。
- **Observe result vs output**：observe result 是动作后看到的环境结果；output 是系统返回或生成的结果，范围可能更广。
- **Outcome vs output**：outcome 是任务想要达成的结果；output 是某一步或系统最终返回的内容。
- **Task completion vs deliverable creation**：完成任务不一定只等于创建文件；deliverable creation 只是可能的完成形式。
- **Broad request vs vague request**：broad request 只规定目标、允许 agent 规划；vague request 可能连目标和约束都不清楚。
- **Multi-step work vs automation**：多步骤工作强调连续目标导向任务；automation 可能只是固定规则流程，不一定有 agent 的决策和观察循环。
- **Delegated task vs autonomous task**：delegated task 强调任务被交给 agent；autonomous task 还强调执行过程中由系统自主决定步骤。
- **Context vs memory**：context 是当前任务可见的信息；memory 通常指跨步骤或跨会话保存的信息，页面没有展开后者。
- **Workspace vs external system**：workspace 是 agent 工作所处的组织环境；external system 是它需要访问或操作的外部目标。
- **Files vs databases**：files 是文档或存储对象；database 更强调结构化、可查询的记录系统，页面只明确提到 files。
- **Office tools vs connectors**：office tools 是执行办公任务的工具；connectors 是把产品接到其他服务或数据源的连接方式。
- **Product-dependent vs deployment-dependent**：product-dependent 表示不同产品不同；deployment-dependent 表示同一能力也可能因安装、配置或环境不同而不同。
- **Supported workflow vs core use**：supported workflow 说明能否支持某流程；core use 说明该流程是否是产品的主要用途。
- **Availability vs capability**：capability 是系统理论上能做什么；availability 是当前套餐、权限或部署是否开放该能力。
- **Permission vs human approval**：permission 是预先限制可访问范围；human approval 是在特定动作前由人批准。
- **Human approval vs human review**：approval 是允许或拒绝继续执行；review 是检查结果或动作，未必每次都构成正式批准。
- **Human oversight vs human-in-the-loop**：oversight 可以是监控；human-in-the-loop 通常表示人在流程中承担审核或决策节点。
- **Sensitive action vs irreversible action**：sensitive action 因内容或风险敏感；irreversible action 因执行后难以撤销，两者可能重叠但不等同。
- **Consequential action vs every action**：页面建议对有后果的动作加强控制，不代表每一次阅读或导航都需要人工批准。
- **Validation vs logging**：validation 判断是否正确；logging 记录发生了什么，记录本身不等于验证。
- **Logging vs audit trail**：logging 可以是一般运行记录；audit trail 更强调完整、可追责和审计用途。
- **Control vs safety**：control 是限制、暂停、检查和记录的机制；safety 是避免伤害或风险的目标。
- **Product boundary vs capability boundary**：product boundary 是产品包含什么；capability boundary 是某项能力能做到什么。
- **Model vs agent**：model 负责处理输入并产生预测或生成结果；agent 还需要规划、工具、状态和行动机制。
- **Agent vs assistant**：agent 不只是更“聪明”的 assistant，而是具备目标导向行动和多步骤执行行为的系统模式。
- **ChatGPT Work vs ChatGPT as a general product name**：页面把 ChatGPT Work 描述为工作导向环境；不要把页面中的产品比较字段自动推广到所有 ChatGPT 版本。
- **Manus vs OpenClaw**：Manus 被描述为通用委托任务产品；OpenClaw 是新兴、可扩展的项目名称，具体打包取决于部署。
- **OpenClaw vs a fixed product specification**：页面对 OpenClaw 的描述明确保留 deployment-dependent，不应把它的能力表述当成固定规格。
- **WorkBuddy vs office suite**：WorkBuddy 是 agentic AI 产品；办公软件套件是被操作或连接的工具集合，两者角色不同。
- **Web research vs browsing**：web research 包含为任务搜集、整理信息；browsing 可以只是打开或阅读网页，不一定形成研究结果。
- **Search vs retrieval**：search 是寻找信息的动作；retrieval 更强调从已有资料中取回相关内容，页面本页主要使用 search / read options。
- **Compare vs recommendation**：compare 组织多个选项的差异；recommendation 还要判断哪些更适合并可能排序。
- **Summary vs decision**：summary 整理信息；decision 是选择下一步或最终选项，智能体不应把总结自动当成用户决定。
- **Booking vs hotel comparison**：比较酒店是信息整理任务；booking 会改变外部系统状态，通常更需要 approval checkpoint。
- **Ask for approval vs perform booking**：请求批准只是等待授权；真正预订才是有外部后果的动作。
- **See screen vs understand screen**：看到屏幕是感知界面状态；不应因此推断系统具有类似人的完整理解。
- **Click / type / navigate vs reasoning**：这些是可观察的界面动作；它们不等同于模型内部推理过程。
- **External system vs world**：页面用 external systems 描述浏览器、桌面、应用、网站和文件，不必把 world 理解成物理机器人环境。
- **Control vs eliminating all risk**：权限、批准、验证和日志可以降低风险，但不代表所有错误或风险都会消失。
- **High-level product descriptions vs fixed feature guarantees**：页面说明产品边界和特征会随时间变化，比较表不能当作永久、全版本保证。
