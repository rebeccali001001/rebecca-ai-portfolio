## Do Not Confuse Candidates

- **RAG vs Retrieval-Augmented Generation**：RAG 是缩写；Retrieval-Augmented Generation 是全称，通常指同一个整体方法。
- **RAG vs retrieval**：retrieval 只是找回资料的任务；RAG 还包括把结果放入上下文并生成回答。
- **RAG vs search**：搜索可以只返回匹配结果；RAG 通常还让模型根据结果组织答案。
- **RAG vs search-only system**：搜索-only 系统不一定生成自然语言回答；RAG 的核心流程包含 generation。
- **RAG vs fine-tuning**：RAG 在运行时提供外部信息；fine-tuning 通过训练改变模型已学习的行为。
- **RAG vs prompt engineering**：提示工程主要改变指令和输入表达；RAG 额外检索并提供外部证据。
- **RAG vs grounding**：grounding 是把回答连到依据的性质或过程；RAG 是实现这种依据连接的一种完整工作流。
- **RAG vs embeddings**：embeddings 是内容的数值表示；RAG 是检索增强生成流程，可能使用 embeddings，但不等于 embeddings。
- **RAG vs vector search**：vector search 是一种找相似资料的方法；RAG 还要构建上下文、生成回答和可能的引用。
- **RAG vs knowledge base**：knowledge base 是资料资产；RAG 是使用资料资产回答问题的系统流程。
- **RAG vs model memory**：RAG 的证据在请求时从外部来源提供；model memory 通常指训练参数中已有的知识。
- **Retrieval vs generation**：retrieval 找回已有资料；generation 产生新的回答文本，两个阶段职责不同。
- **Retriever vs generator**：retriever 负责找资料；generator 负责根据输入写答案。
- **Query vs context**：query 是用户想查什么；context 是系统找到后提供给模型参考的资料。
- **Query vs answer**：query 是问题或请求；answer 是模型生成的回应。
- **Source collection vs model context**：source collection 可能很大；model context 只包含本次选入的一部分。
- **Source document vs retrieved context**：source document 是原始完整资料；retrieved context 是为当前查询选回的内容或片段。
- **Retrieved result vs selected result**：retrieved result 是搜索找回的候选；selected result 是筛选后留下的结果。
- **Candidate vs evidence**：candidate 只是可能有用的候选；evidence 是被采用来支持答案的资料。
- **Relevant vs truthful**：资料和问题相关，不代表资料本身一定真实或最新。
- **Relevant result vs correct answer**：相关结果有助于回答，但不保证最终答案正确。
- **Evidence vs truth**：证据是支持说法的资料；有证据不等于自动获得绝对真相。
- **Citation vs correctness**：有引用不代表回答一定正确；引用还必须真正支持相关主张。
- **Citation vs source**：source 是资料本身；citation 是回答中指向 source 的引用标记。
- **Citation completeness vs citation correctness**：completeness 看重要主张是否都被引用；correctness 看引用是否真的支持主张。
- **Groundedness vs factual truth**：groundedness 看回答是否依托给定上下文；它不自动证明上下文或回答符合现实真相。
- **Context vs context window**：context 是本次提供的内容；context window 是模型可容纳内容的能力或空间。
- **Context limit vs context quality**：context limit 是容量上限；context quality 是放进去的资料是否相关、有用、可靠。
- **Selected evidence vs all source data**：模型通常只看到筛选过的证据，不是整个来源集合。
- **Context selection vs context compression**：selection 决定保留哪些结果；compression 可能进一步缩短已选内容。
- **Search ranking vs answer ranking**：检索排序安排候选资料；它不等于对最终答案质量排序。
- **Retrieval recall vs answer quality**：找回更多相关资料有帮助，但不能保证生成答案质量更高。
- **Recall@k vs precision@k**：recall@k 看相关资料找回了多少；precision@k 看前 k 项中有多少相关。
- **MRR vs NDCG**：MRR 重点关注第一个相关结果的位置；NDCG 能综合不同相关程度和多个位置。
- **Latency vs throughput**：latency 是单次等待时间；throughput 是单位时间能处理的请求量。
- **Freshness vs relevance**：资料很新不一定和问题相关；相关资料也可能已经过时。
- **Trusted source vs authoritative source**：trusted 表示被系统信任；authoritative 通常强调权威性，二者需要业务定义支持。
- **Approved internal document vs any internal document**：approved 文档经过认可；内部存在的文件不一定可以作为正式依据。
- **Database vs vector database**：database 是一般数据存储；vector database 针对向量相似性搜索做了专门支持。
- **Document vs chunk**：document 是较完整的文件；chunk 是从文档中切出的可检索片段。
- **Chunking vs retrieval**：chunking 是预处理切分；retrieval 是查询时找回内容。
- **Embedding vs token**：token 是文字处理单位；embedding 是对内容形成的数值表示。
- **Keyword search vs semantic search**：keyword search 主要匹配字面词；semantic search 主要按含义和表示相似性查找。
- **Lexical search vs vector search**：lexical search 基于词项；vector search 基于向量距离或相似度。
- **Vector search vs retrieval**：vector search 是一种检索实现；retrieval 是更宽的任务概念。
- **Reranking vs initial retrieval**：initial retrieval 先找回候选；reranking 对候选进行更精细的再次排序。
- **Bi-encoder vs cross-encoder**：bi-encoder 分别编码查询和资料，通常更快；cross-encoder 把两者一起评分，通常更精细但更慢。
- **Model context vs model parameters**：context 是本次请求临时提供的输入；parameters 是模型训练后保存的内部数值。
- **External knowledge vs learned knowledge**：external knowledge 来自运行时来源；learned knowledge 来自训练或模型参数。
- **Source metadata vs source content**：metadata 描述来源、类别和时间；source content 是真正被检索和引用的内容。
- **Search result vs cited source**：搜索结果可能只是候选；cited source 是最终回答明确展示的依据。
- **Answer synthesis vs copying source text**：synthesis 是综合资料形成回答；不等于机械复制一段来源内容。
- **Query rewriting vs answer generation**：query rewriting 改善搜索输入；answer generation 产生给用户的最终回答。
- **Query expansion vs retrieval ranking**：query expansion 增加查找线索；ranking 负责排列已经得到的候选。
- **RAG vs long-context prompting**：RAG 选择性地检索资料；long-context prompting 可能直接把大量原文放入上下文。
- **RAG vs tool calling**：RAG 主要检索资料；tool calling 还可能调用计算、交易或实时系统工具。
- **RAG vs agentic RAG**：普通 RAG 可按固定流程执行；agentic RAG 通常由代理动态规划、多次检索或验证。
- **RAG vs graph RAG**：RAG 是总类；graph RAG 以图结构或知识图谱作为增强方式。
- **Source conflict vs hallucination**：source conflict 是来源彼此矛盾；hallucination 是模型生成没有依据或不存在的内容。
- **Retrieval failure vs generation failure**：retrieval failure 是找不到好资料；generation failure 是有资料却没能正确作答。
- **Abstention vs failure**：abstention 是在证据不足时有意不作答；failure 是系统未能完成任务，可能没有安全处理。
- **Human-like understanding vs retrieve-then-generate analogy**：图书管理员类比只解释流程，不表示系统具有人类式理解。
- **Help center vs internal policy source**：help center 是面向账户设置的日常来源；internal policy source 是企业内部政策资料。
- **Input vs output**：input 是进入系统的问题；output 是系统返回的回答。
- **AI / System vs model**：AI/System 可以包含应用、检索器、数据库和模型；model 只是其中负责处理或生成的一部分。
- **Video/poster/captions vs RAG mechanism**：视频、封面图和字幕是页面呈现资源，不是 RAG 检索或生成机制。
