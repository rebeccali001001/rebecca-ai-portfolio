## Do Not Confuse Candidates

- Latency vs Throughput：latency 是单个请求或结果需要等待多久；throughput 是一段时间内完成多少工作。
- Latency vs Response Time：两者常被当作近义词；本页的 latency 重点是从请求到结果可用的等待时间，而 response time 的具体边界可能因系统定义不同。
- Latency vs End-to-End Latency：latency 可以只指某一环节；end-to-end latency 覆盖从请求发出到最终结果返回的完整路径。
- Latency vs Model Speed：latency 包含系统、网络、上下文和生成时间；model speed 只描述模型自身的计算速度。
- Latency vs Model Quality：latency 衡量等待时间；model quality 衡量结果有用或准确的程度，快不代表质量高。
- Low Latency vs High Throughput：系统可能单次响应很快，也可能一次处理很多请求；低延迟和高吞吐量不是同一个目标。
- Time to First Token vs Time to Complete Response：TTFT 只到第一个词元出现；完整响应时间要等全部内容到达。
- Time to First Token vs Time to First Byte：TTFT 关注模型首个词元；TTFB 关注网络响应首个字节，测量边界不同。
- Time to Last Token vs Time to Completion：最后一个词元到达通常接近完成时间，但完整完成还可能包含结束、传输或应用处理开销。
- First Output vs Complete Response：首个输出只是回答开头；完整响应包含全部生成内容。
- First Pause vs Time to First Token：电话类比中的 first pause 是帮助理解等待的非技术表达；time to first token 是可测量的技术指标。
- Streaming vs Low Latency：流式输出可以让首段内容更早可见，但不必然减少生成完整回答所需的总时间。
- Streaming vs Faster Model：流式传输改变内容交付方式；更快的模型改变计算速度，两者不是同一件事。
- Waiting Time vs Technical Causes：电话类比解释用户等待的体验，不等于解释系统延迟的底层原因。
- System Latency vs Network Latency：系统延迟来自系统处理；网络延迟来自数据传输，可能共同构成总延迟。
- Context Preparation vs Generation：上下文准备发生在生成前；generation 是模型逐个产生输出词元的阶段。
- Input Processing vs Output Generation：input processing 处理提示和上下文；output generation 产生回答内容。
- Prefill vs Decode：prefill 通常处理输入上下文；decode 通常生成输出词元，不应混为同一阶段。
- Queue Time vs Service Time：queue time 是请求等待被处理的时间；service time 是系统实际处理请求的时间。
- Network Round Trip vs End-to-End Latency：RTT 只描述网络来回时间；端到端延迟还包括应用、上下文、模型和生成等阶段。
- Average Latency vs Tail Latency：平均值描述整体平均等待；尾部延迟关注最慢的一部分请求，不能互相替代。
- P50 vs P95 vs P99：这些是不同百分位位置；P99 关注比 P95 更慢的尾部请求。
- Latency Spike vs High Average Latency：尖峰是短时突然变高；平均延迟高可能是长期普遍偏慢。
- Latency Variance vs Tail Latency：variance 描述数值波动；tail latency 描述慢请求分布位置，含义不同。
- Latency Metric vs Throughput Metric：延迟指标看等待时间；吞吐量指标看单位时间完成工作量。
- Latency Target vs Latency Measurement：目标是希望达到的时间；测量是实际观察到的时间。
- Latency Budget vs Timeout Budget：latency budget 是设计目标或时间分配；timeout budget 是超时前允许等待的上限。
- Response Deadline vs Timeout：deadline 是应当完成的时间点；timeout 是超过允许等待后系统停止等待或报错的状态。
- Result Available vs Request Received：收到请求只是流程开始；结果可用需要经过准备、运行和生成。
- Model Run vs Complete Response：模型开始运行不代表完整回答已经返回。
- Generate Tokens vs Return the Result：生成词元是内部产生内容；返回结果是把内容交付给应用。
- Output Rate vs Time to First Token：output rate 描述输出持续产生的速度；TTFT 描述首个输出出现前的等待。
- Tokens per Second vs Time per Token：TPS 是单位时间生成多少词元；time per token 是生成一个词元平均需要多久，数值关系相反。
- Low Latency vs Low Total Work：优化可以降低等待，但低延迟不必然意味着系统总工作量小。
- Large Context vs Large Total Work：大文档或大上下文通常意味着更多处理，但页面只说明可能带来更长的生成前等待，不应推断固定比例。
- Small Context vs Fast Complete Response：小上下文可能让回答更早开始，但完整响应仍取决于输出长度、生成速度和传输。
- Chat Reply vs Document Question Answering：聊天回复是日常短问题示例；文档问答是带大型上下文的业务示例。
- Phone Call vs AI Inference：电话只是解释等待体验的类比；AI inference 才是模型计算过程本身。
- Analogy vs Mechanism：analogy 用熟悉场景帮助理解；mechanism 是真实技术如何产生延迟。
- Throughput vs Capacity：throughput 是当前一段时间完成的工作量；capacity 是系统可承载的能力上限。
- Model Quality vs Accuracy：本页将 quality 说明为有用或准确；accuracy 是更具体的一种质量衡量方式。
- Useful Result vs Accurate Result：有用性和准确性可能同时存在，也可能不一致；用户觉得有帮助不自动证明事实正确。
- System Speed vs Model Speed：system speed 覆盖整个处理链路；model speed 只覆盖模型计算。
- Response vs Output：页面中两者都可表示系统返回的内容；在更严格的系统语境中 output 可能指内部产物，response 可能指对外返回消息。
- Request vs Prompt：request 可以包含整个系统请求；prompt 通常指给模型的文字或任务输入。
- Context vs Prompt：prompt 是主要任务或指令；context 是围绕 prompt 提供的辅助信息，二者可以一起组成模型输入。
- Token vs Word：token 是模型处理的单位，不一定等于自然语言中的一个完整单词。
- First Token vs First Word：首词元不一定是首个完整单词，因为一个单词可能被切成多个词元。
- Time to First Token vs User-Perceived Latency：TTFT 是具体指标；用户感知延迟还可能受到界面、网络和渲染影响。
- Complete Response vs Complete Conversation：complete response 是一次 AI 回答全部到达；complete conversation 是电话类比中的整段交流。
- Latency vs Availability：latency 是多久可用；availability 是服务是否可用，时间快慢和能否使用不同。
- Latency vs Timeout：latency 是测得的耗时；timeout 是因为超过允许等待而终止或失败。
- Latency Optimization vs General Optimization：latency optimization 明确以减少等待为目标；general optimization 可能优化成本、质量或资源等其他目标。
- Latency Bottleneck vs Slowest Component：bottleneck 是对整体性能影响最大的限制因素；最慢的单个组件不一定是整体瓶颈。
- SLO vs SLA：SLO 是内部或服务目标；SLA 通常是对客户或合作方的服务承诺，约束和后果可能不同。
- Page-Level Concept vs Advanced Serving Technique：本页解释延迟的定义、用户体验和五步流程；KV cache、continuous batching、speculative decoding 等高级技术只属于 Potential Missing Concepts，不应当当作页面已详细讲授。
