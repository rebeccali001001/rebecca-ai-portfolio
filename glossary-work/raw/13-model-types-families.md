## Do Not Confuse Candidates

- **Model family vs specific model**：家族是一组相关发布版本的共享名称；具体模型是其中一个有自己 limits、pricing 和 behavior 的版本。
- **Model family vs model type**：family 回答“谁构建、哪些模型属于一起”；type 回答“模型处理什么信息或任务”。
- **Provider vs family**：provider 是组织；family 是该组织发布的一组相关模型名称。
- **Family name vs version**：GPT、Claude 等可以是家族名；generation 或 release 才表示某一代或某个具体版本。
- **Model vs product**：模型提供 AI capability；产品还包括 interface、policies、data 和 operations。
- **Model vs application**：模型是能力组件；application 是把模型放进真实使用场景的产品或工作流。
- **Product vs product layer**：product 是完整面向用户的系统；product layer 强调包装模型的那一层。
- **Model capability vs model quality**：capability 是能不能处理某类输入输出；quality 是结果是否准确、有用、稳定或安全。
- **Modality vs capability**：modality 是信息形式；capability 是模型用这种信息完成的工作。
- **Input modality vs output modality**：一个描述模型接收什么，一个描述模型产生什么；二者可能不同。
- **Multimodal vs all modalities**：多模态只表示至少涉及多种模态，不代表支持文字、图像、音频、视频的全部组合。
- **Language model vs LLM**：language model 是更宽的语言模型类别；LLM 强调规模较大的语言模型。
- **LLM vs multimodal model**：LLM 主要围绕语言；multimodal model 处理多种信息形式，二者可能重叠但不等价。
- **Foundation model vs LLM**：foundation model 是可复用的广泛模型类别；LLM 是其中以语言为重点的一类，二者不是同义词。
- **Foundation model vs multimodal model**：foundation model 描述可复用的训练和用途范围；multimodal model 描述支持的模态。
- **Multimodal model vs multimodal AI**：前者是模型；后者可以包含模型、产品、工具、界面和运营的更大系统。
- **General-purpose vs specialized**：通用型支持很多日常任务；专用型集中优化某个任务或能力。
- **Reasoning vs general-purpose**：推理型强调更复杂的多步骤问题；通用型强调任务覆盖面，不一定在复杂推理上最强。
- **Coding vs code modality**：Coding 是按用途定义的模型类别；code 是模型处理的一种信息形式。
- **Embedding vs generation**：embedding 产出向量表示供搜索或检索；generation 产出新的文字、图片、视频或其他内容。
- **Image model vs image generation**：image model 是模型类别；image generation 是其中一种具体用途。
- **Speech vs audio**：speech 特指人类语音；audio 范围更大，还包括音乐和环境声。
- **Text vs language**：text 主要指文字形式；language 还可以包含更广的语言理解和生成能力。
- **Image vs video**：image 是静态视觉信息；video 是随时间变化的视觉序列，可能还带音频。
- **Speech recognition vs text-to-speech**：前者把声音转成文字；后者把文字变成声音。
- **Audio-to-text vs prompt-to-music**：前者是转写或识别；后者是根据描述生成音乐。
- **Text-to-image vs image-to-image**：前者主要从文字生成图像；后者以图像为输入生成或修改图像。
- **Text-to-video vs video understanding**：前者生成视频；后者理解已有视频内容。
- **Model name vs product name**：一个名称可能指模型、家族、API 或产品，不能只凭品牌名断定层级。
- **Brand vs family**：品牌是更宽的市场或组织标识；family 是相关模型版本的技术归属。
- **Size vs tier**：size 通常描述模型规模；tier 可能描述服务级别、价格或产品档位，二者不必相同。
- **Mini vs small model**：mini 可能是厂商命名的 tier，不一定严格等于参数更少的 small model。
- **Pro vs larger model**：pro 可能表示服务档位或能力组合，不一定只表示参数更多。
- **Capability label vs guaranteed capability**：名称中的 reasoning 或 image 是提示性标签，不等于所有任务都可靠。
- **Official example vs complete catalog**：页面列出的是代表性官方 family，不是完整市场目录。
- **Current release vs permanent name**：当前可用版本和家族名称都会随时间变化，不能当作永久不变。
- **Model limits vs model quality**：limits 是边界或约束；quality 是在边界内做得好不好。
- **Pricing vs size**：价格可能与规模相关，但也会受供应、服务档位和产品策略影响。
- **Input vs prompt**：prompt 是一种引导模型的输入；图片、视频、声音也可以是 input，但不一定是 prompt。
- **Output vs capability**：output 是一次具体结果；capability 是模型可以反复提供的一类能力。
- **Understand vs generate**：理解输入和生成输出是不同动作，同一个模型可以同时具备两者。
- **Search vs retrieval**：search 强调寻找；retrieval 强调把相关结果取回给模型或流程使用。
- **Embedding vs vector database**：embedding 是向量表示或生成它的模型；vector database 是存储和检索向量的系统。
- **Multimodal model vs multimodal interface**：模型负责计算；界面负责让用户以多种形式与模型交互。
- **Model family vs model ecosystem**：family 是一个相关版本集合；ecosystem 还包含提供商、产品、工具、社区和部署方式。
- **Specific release vs deployment endpoint**：release 是模型版本；endpoint 是访问该版本的服务入口。
- **Product policy vs model behavior**：政策是产品施加的规则；behavior 是模型在输入下的表现，二者可能共同影响最终结果。
- **Provider capability vs product capability**：提供商的模型可能支持某能力，但具体产品未必开放或实现该能力。
- **Multimodal model vs generative AI**：multimodal 描述信息形式；generative AI 描述是否生成新内容，两个维度可以交叉。
- **Reasoning model vs reasoning capability**：前者是模型类别；后者是某个模型表现出的能力，不必对应独立 family。
- **Image model vs vision model**：image model 可泛指图像输入输出；vision model 常更强调视觉理解，不能自动视为完全同义。
- **Speech model vs audio model**：speech model 重点是语音；audio model 可能处理音乐、环境声等更广音频。
- **Model family vs model architecture**：family 是发布和命名归属；architecture 是内部技术结构。
- **Model type vs model architecture**：type 按用途或输入输出分类；architecture 描述模型如何构建。
- **Model size vs model parameter count**：size 是宽泛标签；parameter count 是一种更具体的规模衡量方式。
- **Open model vs available model**：能使用某个模型不等于其权重、源码或训练数据开放。
- **Local model vs provider family**：local/cloud 描述部署位置；provider/family 描述来源和归属。
- **Multimodal input vs multi-turn input**：多模态说信息形式多种；多轮说交互回合多，不是同一概念。
- **Video generation vs music generation**：前者产出动态图像；后者产出声音或音乐，虽都属于生成但输出模态不同。
- **Text-to-text vs language understanding**：文本到文本是输入输出映射；语言理解是内部或任务能力，不是同一层级。
- **Official documentation vs universal standard**：官方文档说明某个提供商的命名和产品；不代表整个行业都遵循同一规则。
- **Representative family vs exhaustive list**：代表性示例用于解释概念；不能据此认为页面列出了全部模型。
- **Overlapping categories vs hierarchy**：可重叠类别允许一个模型归入多类；层级则表示明确的上下位关系。
