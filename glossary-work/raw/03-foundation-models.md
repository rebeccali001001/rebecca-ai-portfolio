## Do Not Confuse Candidates

- Foundation Model vs finished product: a foundation model is a reusable base; a finished product also contains an interface, data, rules, integrations, and operations.
- Foundation Model vs base model: these are usually near-synonyms in this page’s context; “foundation” emphasizes broad reuse and “base” emphasizes the starting point.
- Foundation Model vs fine-tuning: the foundation model is the broadly trained starting artifact; fine-tuning is additional training applied afterward.
- Foundation Model vs database: a foundation model encodes learned behavior in parameters; a database stores explicit records for lookup.
- Foundation Model vs LLM: an LLM is language-focused; a broadly trained reusable LLM can be used as a foundation model, but the terms are not identical.
- Foundation Model vs language model: “foundation” describes breadth and reuse; “language” describes the modeled data domain.
- Foundation Model vs Generative AI: “foundation model” describes a reusable trained base; “Generative AI” describes systems that create new content.
- Foundation Model vs multimodal model: “foundation” describes training and downstream reuse; “multimodal” describes the types of information handled.
- Foundation Model vs application: the model supplies a reusable capability; the application turns it into a concrete user-facing use.
- Foundation Model vs system: a system may include one or more models plus data, rules, interfaces, tools, and operations.
- Broadly trained vs fully capable: broad training creates general capability but does not mean the model is perfect at every task.
- Broadly trained vs current: broad training does not guarantee current knowledge; training data can have a knowledge cutoff.
- Broadly trained vs autonomous: a broadly trained model is not automatically an agent or an independent decision-maker.
- Base model vs specialized model: the base model is the general starting point; the specialized model is adapted for a narrower task or domain.
- Pre-training vs adaptation: pre-training builds broad capability; adaptation specializes an existing model for a target task.
- Training vs inference: training learns or changes parameters; inference applies a trained model to new input.
- Training from zero vs reuse: training from zero creates a separate model; reuse starts from an existing broadly trained base.
- Prompting vs fine-tuning: prompting changes the instructions or context at use time; fine-tuning changes model parameters through additional training.
- Prompting vs retrieval: prompting gives instructions or context; retrieval finds relevant external information to put into context.
- Retrieval vs database: retrieval is the act of finding information; a database is a storage system that can support retrieval.
- Retrieval vs parameters: retrieval fetches external records; parameters contain learned patterns and are not individually browsable records.
- Retrieval vs fine-tuning: retrieval adds context at request time; fine-tuning changes the model through training.
- Tool use vs retrieval: retrieval is one possible tool capability; tools can also calculate, browse, call APIs, or take actions.
- Context vs knowledge: context is information supplied for a particular request; knowledge may be encoded in parameters or stored externally.
- Input vs context: input is the full payload sent to the model; context is supporting information inside or around that payload.
- Input vs request: input is the data or text processed; a request is the message or operation asking the system to process it.
- Output vs result: output is what the model emits; result may refer to the complete system result after post-processing or tool use.
- Model vs algorithm: a model is learned structure or parameters; an algorithm is a procedure used to train, adapt, or run it.
- Model vs architecture: a model is a configured learned artifact; architecture is the structural design shared by a model family.
- Model parameters vs hyperparameters: parameters are learned values; hyperparameters are settings chosen to control training or use.
- Model parameters vs database records: parameters distribute learned patterns across numeric values; database records are explicit entries that can be retrieved individually.
- Model capability vs application fit: capability is what the model can do; fit is whether that ability meets a particular application’s requirements.
- Application fit vs evaluation: fit is the property being judged; evaluation is the process used to judge it.
- Application vs use case: an application is the implemented system or feature; a use case is the situation or purpose it serves.
- Product vs workflow: a product is a complete user-facing system; a workflow is a sequence of steps that may use products, people, and tools.
- Interface vs model: an interface is how users or software interact with a system; the model is the underlying learned component.
- Rules vs prompts: rules may be enforced by application logic; prompts are instructions supplied to guide model behavior and may not be sufficient as a hard control.
- Operations vs model: operations keep the product running; they are not the learned model itself.
- Knowledge encoded in parameters vs explicit knowledge: parameters represent distributed learned behavior; explicit knowledge is stored as identifiable text or records.
- Database vs knowledge base: a database is a storage technology; a knowledge base is a curated information collection that may use a database.
- Grounded answer vs accurate answer: grounding ties an answer to supplied evidence; it does not by itself prove the evidence is correct.
- Cited answer vs correct answer: citations make claims more checkable; a citation can still be wrong, irrelevant, or incomplete.
- Cited draft vs final answer: a cited draft may still require human review and approval before delivery.
- Hallucination vs uncertainty: hallucination is an unsupported or false claim; uncertainty is the model’s lack of confidence or evidence.
- Confidence vs probability: confidence may be an informal score; a probability has a defined probabilistic interpretation and may need calibration.
- Safety vs reliability: safety concerns harmful or unacceptable behavior; reliability concerns consistent operation and performance.
- Privacy vs security: privacy concerns protecting information and people; security concerns protection against unauthorized access or attack.
- Fairness vs accuracy: overall accuracy can hide unequal performance or treatment across groups.
- Explainability vs transparency: explainability concerns understandable behavior or reasons; transparency concerns disclosure about data, operation, and limits.
- Robustness vs reliability: robustness concerns variation, noise, and unusual input; reliability is broader consistency over time and conditions.
- Quality vs boundary: quality measures how good an output is; a boundary describes where the model should or should not be relied upon.
- Evaluation vs monitoring: evaluation is a planned test or measurement; monitoring observes a deployed system continuously or periodically.
- Offline evaluation vs online evaluation: offline evaluation uses stored data; online evaluation measures behavior in live traffic or production.
- Benchmark vs test case: a benchmark is a standardized comparison set; a test case is one chosen scenario or input.
- Accuracy vs precision vs recall: accuracy counts all correct outcomes; precision focuses on predicted positives; recall focuses on actual positives found.
- Metric vs objective: a metric measures performance; an objective is what training or decision-making is trying to optimize.
- Generalization vs memorization: generalization works on new cases; memorization mainly reproduces training examples.
- Distribution shift vs data drift vs concept drift: distribution shift is the broad mismatch; data drift changes inputs; concept drift changes input-output relationships.
- Model drift vs data drift: data drift is a change in incoming data; model drift is the resulting change or deterioration in deployed model behavior.
- Domain adaptation vs fine-tuning: domain adaptation targets a subject area; fine-tuning is a training mechanism that may be used for it.
- Domain knowledge vs model knowledge: domain knowledge is subject-specific information; model knowledge is what is represented in a particular model.
- General model vs domain-specific model: a general model supports many settings; a domain-specific model is adapted for one domain.
- LLM vs generative AI: an LLM is a language model family; Generative AI is a broader capability category that can include text, image, audio, and video generation.
- Vision model vs image-generation model: a vision model may understand images; an image-generation model produces images, though one model can do both.
- Text model vs language model: text model is a broad description of data modality; language model emphasizes learned linguistic patterns.
- Multimodal model vs cross-modal mapping: a multimodal model handles multiple modalities; cross-modal mapping links representations or outputs across them.
- Writing assistant vs language model: the assistant is a product use; the language model is the underlying capability.
- Support assistant vs policy question: a support assistant is the system; a policy question is one type of input.
- Approved context vs arbitrary context: approved context is trusted and authorized; arbitrary context may be unverified, stale, or malicious.
- Trusted source vs authoritative source: a source may be trusted for a workflow without being the most authoritative source on every subject.
- Source relevance vs source quality: relevance is how closely a source matches the question; quality is how trustworthy and useful it is.
- Citation completeness vs citation correctness: completeness asks whether important claims have citations; correctness asks whether citations actually support them.
- Retrieval precision vs retrieval recall: precision asks how many retrieved items are relevant; recall asks how much relevant information was found.
- Chunking vs retrieval: chunking splits documents; retrieval selects relevant chunks.
- Embedding vs vector database: an embedding is a numeric representation; a vector database stores and searches such representations.
- Semantic search vs keyword search: semantic search matches meaning; keyword search primarily matches literal terms.
- Reranking vs retrieval: retrieval finds candidates; reranking orders those candidates by relevance.
- Context window vs context budget: a context window is the model’s maximum capacity; a context budget is the portion allocated to a particular request.
- Token vs word: a token is a model-processing unit and may be smaller or larger than a word.
- Prompt template vs system prompt: a template is a reusable construction pattern; a system prompt is a high-priority instruction instance.
- System prompt vs developer instruction vs user prompt: these are different instruction sources with different priorities and responsibilities.
- Zero-shot vs few-shot: zero-shot uses instructions without examples; few-shot includes a small number of examples.
- In-context learning vs fine-tuning: in-context learning changes behavior temporarily through prompt examples; fine-tuning changes parameters through training.
- Instruction tuning vs prompting: instruction tuning trains a model to follow instructions; prompting supplies instructions at use time.
- Alignment vs safety tuning: alignment is broad behavior matching; safety tuning is focused on reducing unsafe behavior.
- RLHF vs human review: RLHF uses human preferences during training; human review checks outputs during use or operations.
- Guardrail vs rule: a rule is a constraint; a guardrail is a control designed to keep a system within safe or acceptable behavior.
- Prompt injection vs jailbreak: prompt injection inserts instructions that manipulate behavior; jailbreak is the broader attempt to bypass restrictions.
- Data poisoning vs prompt injection: poisoning corrupts data before or during learning/retrieval; injection manipulates an individual request or context.
- Model extraction vs model inversion: extraction copies behavior; inversion attempts to infer training data or sensitive attributes.
- Hosted model vs local model: hosted models run on a provider’s infrastructure; local models run on the user’s or organization’s hardware.
- Open model vs closed model: open models expose some weights or access under terms; closed models keep internal details or access restricted.
- Cloud model vs hosted model: cloud model describes infrastructure location; hosted model describes provider operation; the terms can overlap.
- Model provider vs model consumer: the provider develops or serves the model; the consumer integrates or uses it.
- Portability vs interoperability: portability concerns moving a component; interoperability concerns components working together.
- Compatibility vs interchangeability: compatibility means a component can work in a system; interchangeability means it can replace another with minimal change.
- Model routing vs tool routing: model routing chooses among models; tool routing chooses among external functions.
- Model cascade vs fallback: a cascade intentionally tries levels of capability; a fallback is used when the preferred path is unavailable or unsuitable.
- Canary deployment vs A/B test: canary limits initial release exposure; A/B testing compares variants under an experiment.
- Shadow evaluation vs production use: shadow evaluation observes a model without using its output; production use lets output affect users or decisions.
- Rollout vs rollback: rollout increases exposure to a new version; rollback returns to an earlier version.
- Monitoring vs audit logging: monitoring watches health and behavior; logging records events for later review.
- Model registry vs model repository: a registry tracks versions and metadata; a repository may store model artifacts; tools can combine both roles.
- Versioning vs change management: versioning records changes; change management governs how changes are reviewed and released.
- MLOps vs DevOps: MLOps includes DevOps-like operations plus data, model, evaluation, drift, and retraining concerns.
- Deployment readiness vs production readiness: deployment readiness concerns whether a model can be released; production readiness includes sustained real-world operation.
- Latency vs throughput: latency is time per response; throughput is the volume handled per unit time.
- Availability vs reliability: availability is readiness to respond; reliability includes consistent correct operation over time.
- Cost vs compute: compute is processing resource; cost is the financial or operational expense of using resources.
- Scalability vs throughput: throughput is current handling rate; scalability is the ability to increase handling as demand grows.
- API vs serving endpoint: an API is an interface contract; an endpoint is a concrete address or entry point.
- Function calling vs tool use: function calling is one structured way to invoke a tool; tool use includes the broader capability and orchestration.
- Tool result vs model output: tool result comes from an external function; model output is generated by the model, possibly after using tools.
- Orchestration vs automation: orchestration coordinates multiple components; automation may be a single rule-driven action.
- Agent vs foundation model: an agent is an acting system; a foundation model is a reusable model component that an agent may use.
- Planning vs generation: planning chooses actions or steps; generation produces text, images, or another content artifact.
- Human-in-the-loop vs human-on-the-loop: human-in-the-loop requires active review or approval; human-on-the-loop supervises a system that may act automatically.
- Human approval vs human review: review examines an output; approval explicitly authorizes it.
- Escalation vs fallback: escalation sends a case to a person or stronger process; fallback uses an alternate automated path.
- Error handling vs safety control: error handling addresses failures; safety controls address harmful or unacceptable behavior, though they can overlap.
- Retry vs rollback: retry repeats a request; rollback changes the deployed version back.
- Rate limit vs quota: a rate limit controls request speed; a quota controls total allowed usage over a period.
- Context assembly vs context injection: assembly selects and organizes context; injection adds it to the model input.
- Memory vs context: memory is retained information; context is the information provided for a current request.
- Short-term memory vs long-term memory: short-term memory applies within a task or session; long-term memory persists across interactions.
- Conversation history vs knowledge base: history is prior interaction context; a knowledge base is curated external information.
- State vs memory: state describes current progress or situation; memory is retained information that may help recover or continue state.
- Pre-processing vs post-processing: pre-processing prepares inputs before inference; post-processing checks or transforms outputs afterward.
- Output filtering vs output validation: filtering blocks disallowed content; validation checks structure, correctness, or requirements.
- Schema vs format: a schema defines allowed fields and values; a format is the broader presentation or encoding arrangement.
- Structured output vs free-form output: structured output follows a defined schema; free-form output has fewer structural constraints.
- JSON vs schema: JSON is a data encoding; a schema describes what valid JSON should contain.
- Input contract vs output contract: an input contract defines accepted requests; an output contract defines required results.
- Model interface vs user interface: the model interface is for software calls; the user interface is for human interaction.
- Model architecture vs system architecture: model architecture describes internal model structure; system architecture describes the full surrounding product.
- Model type vs model family: a type is a category; a family is a related set of specific models.
- Text model vs text generation: text model is a model category; text generation is an operation or capability.
- Video metadata vs video content: metadata describes the media; the content is the audio-visual material itself.
- Captions vs transcript: captions are time-aligned and often include accessibility cues; a transcript is a text record that may not be time-aligned.
- MP4 vs H.264 vs AAC: MP4 is a container; H.264 is a video codec; AAC is an audio codec.
- VTT vs captions: VTT is a file format for timed text; captions are the user-facing text content.
- Poster image vs thumbnail: a poster is used before playback; a thumbnail is a general preview image, though they can be the same asset.
- Azure Neural voice vs foundation model: Azure Neural voice is a speech service; a foundation model is a broad reusable model concept.
- Analogy vs definition: an analogy makes an idea intuitive; a definition states what it means.
- Beginner-friendly explanation vs technical specification: a beginner explanation simplifies; a technical specification defines exact behavior and constraints.
- Related concept vs synonym: a related concept is connected but different; a synonym has the same or nearly the same meaning.
- Alias vs synonym: an alias can be an alternate label without identical meaning; a synonym implies near-equivalent meaning.
- Parent-child relationship vs adaptation relationship: parent-child is strict conceptual containment; adaptation is a process or pathway relationship.
- “Prompting · RAG · Fine-tuning · Tools” vs strict hierarchy: these are presented as related adaptation paths, not a strict parent-child tree.
- Model parameters vs model records: parameters are numeric learned values; model records are not necessarily explicit facts that can be looked up.
- Generalization vs transferability: generalization concerns unseen examples in a related setting; transferability concerns reuse across tasks or domains.
- Reusability vs adaptability: reusability is using the same model multiple times; adaptability is how easily it can be specialized.
- Capability coverage vs use-case coverage: capability coverage describes model abilities; use-case coverage describes intended scenarios handled.
- Quality bar vs acceptance criterion: a quality bar is a minimum level; an acceptance criterion is a specific condition for approval.
- Reliability target vs safety target: a reliability target concerns stable operation; a safety target concerns avoiding harm.
- Current information vs knowledge cutoff: current information is up to date; knowledge cutoff is the latest point represented by training data.
- Freshness vs authority: freshness is how current data is; authority is how trustworthy or official its source is.
- Source authority vs source relevance: authority concerns trustworthiness; relevance concerns fit to the question.
- Evidence-backed answer vs grounded answer: both emphasize support, but groundedness specifically ties output to supplied context.
- Faithfulness vs factuality: faithfulness measures adherence to source context; factuality concerns whether claims are true in the world.
- Answerability vs confidence: answerability depends on whether evidence is sufficient; confidence is how certain the model appears.
- Abstention vs refusal: abstention is declining due to insufficient evidence or confidence; refusal may be required by policy or safety.
- Safe deployment vs responsible deployment: safe deployment emphasizes controls against harm; responsible deployment also includes fairness, transparency, privacy, and accountability.
- Governance vs operations: governance sets rules and oversight; operations runs and maintains the system.
- Data governance vs model governance: data governance manages data; model governance manages models, risks, and approvals.
- Audit trail vs provenance: an audit trail records actions and changes; provenance traces where data or outputs came from.
