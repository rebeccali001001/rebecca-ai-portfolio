## Do Not Confuse Candidates

- **Code generation vs coding agent**: Code generation produces or transforms code; a coding agent adds tools and actions around that capability.
- **Code generation vs compiler**: Code generation uses a model to draft or transform source code; a compiler translates code according to formal language rules.
- **Generated code vs guaranteed correct code**: A model output may contain bugs, insecure patterns, or wrong assumptions, so generation is not a correctness guarantee.
- **Source code vs compiled code**: Source code is human-readable program text; compiled code is a transformed form produced for execution.
- **Code generation vs code execution**: Generation writes or changes code; execution runs code and observes what it does.
- **Code generation vs code completion**: Generation can create a larger implementation from a task; completion often continues a partial code fragment.
- **Code generation vs code translation**: Generation is the broader capability; translation is one use case that rewrites code between languages or forms.
- **Code generation vs code synthesis**: These overlap, but synthesis often emphasizes constructing a program from a specification or examples.
- **New code vs modified code**: New code did not previously exist for the task; modified code changes an existing implementation.
- **Code context vs task instruction**: Context supplies relevant project information; the instruction describes what work should be done.
- **Code context vs entire repository**: Relevant context may be only the files and patterns needed for the task, not every repository file.
- **Project context vs model memory**: Project context is supplied for the current task; model memory or learned patterns come from training or application state.
- **Function signature vs function implementation**: A signature describes the interface; an implementation contains the code that performs the behavior.
- **Function vs module**: A function is usually a callable unit; a module is a larger separable project component that may contain several functions.
- **Pattern vs requirement**: A pattern describes how existing code is commonly written; a requirement says what the new code must do.
- **Learned pattern vs retrieved code example**: A learned pattern is internal model knowledge; a retrieved example is source context supplied at runtime.
- **Code token vs source-code line**: A token is a model-processing unit; a line is a formatting or source-organization unit.
- **Likely continuation vs correct continuation**: The model predicts what is probable, not what is necessarily correct for the project.
- **Prediction vs verification**: Prediction proposes an output; verification checks whether it meets requirements.
- **Review vs testing**: Review examines code, often by a person; testing runs checks against behavior.
- **Automated check vs human review**: An automated check follows programmed criteria; human review can interpret requirements and risks more broadly.
- **Bug vs security issue**: A bug is unintended behavior; a security issue is a weakness that can expose or misuse a system, though one defect can be both.
- **Error vs failure**: An error is a problem in code or reasoning; a failure is an unsuccessful test, execution, or outcome.
- **Boundary case vs failure case**: A boundary case targets a limit; a failure case targets invalid input, errors, or unsuccessful behavior.
- **Normal case vs happy path guarantee**: A normal case is one expected scenario; passing it does not prove all other cases work.
- **Feedback vs instruction**: An instruction states the desired work; feedback reports what happened and what should improve.
- **Failure feedback vs failure itself**: A failure is the bad outcome; failure feedback is the information used to repair it.
- **Refinement vs regeneration**: Refinement improves a draft using evidence; regeneration creates another output, possibly from changed inputs.
- **Intended behavior vs observed behavior**: Intended behavior is what the code should do; observed behavior is what it actually does when checked or run.
- **Preserve intended behavior vs preserve exact implementation**: Translation may preserve functionality while changing syntax, libraries, or internal structure.
- **SQL query vs database schema**: A query asks for or changes data; a schema describes tables, fields, and relationships.
- **Schema vs function signature**: A schema describes data organization; a function signature describes a callable code interface.
- **Proposed query vs validated query**: A generated query is a draft; validation checks syntax, permissions, results, and safety.
- **Test case vs test suite**: A test case checks one scenario; a suite groups multiple tests.
- **Normal, boundary, and failure cases vs complete test coverage**: These categories improve coverage but do not guarantee every behavior is tested.
- **Compiler vs model**: A compiler applies deterministic language rules; a model predicts a likely code sequence from learned patterns and context.
- **Language rules vs project conventions**: Language rules are formal requirements; project conventions are local style or architecture choices.
- **Correct code vs compilable code**: Code can compile and still have incorrect logic, poor requirements fit, or security flaws.
- **Security issue vs security review**: A security issue is a flaw; a security review is the process of looking for flaws.
- **Code review vs code acceptance**: Review is an examination; acceptance is the decision that the result is ready for use.
- **Repository tools vs tool calling**: Repository tools are specific capabilities; tool calling is the model’s mechanism for requesting or invoking a tool.
- **Execution vs feedback loop**: Execution is one run; a feedback loop uses execution or checks to guide another version.
- **Coding agent vs AI-assisted coding**: A coding agent is an acting system with tools; AI-assisted coding can be a broader human-led workflow.
- **Generative AI vs code generation**: Generative AI is the broad category; code generation is its source-code use case.
- **Foundation model vs code-generation model**: A foundation model is broadly reusable; a code-generation model emphasizes software-code outputs.
- **Tool calling vs autonomous action**: Tool calling is an invocation mechanism; autonomy concerns how independently the system chooses and sequences actions.
- **Model capability vs generated result**: Capability is what the model can potentially do; a particular result can still be wrong or incomplete.
- **Natural-language request vs formal specification**: A request may be ambiguous; a formal specification defines behavior more precisely.
- **Code transformation vs behavior preservation**: Transformation changes representation; preservation is a requirement that intended functionality remain.
- **Review/test vs deployment**: Review and testing assess code; deployment releases it into an environment.
- **Code generation vs software development**: Code generation is one capability; software development also includes requirements, design, review, testing, deployment, and maintenance.
