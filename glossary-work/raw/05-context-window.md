## Do Not Confuse Candidates

- Context Window vs Memory: the context window is the information available for the current model operation; memory is information stored or retrieved across interactions.
- Context Window vs Model Knowledge: the context window contains information supplied now; model knowledge consists of patterns learned during training.
- Context Window vs Maximum Answer Length: the context window covers available input plus generated tokens according to model/API design; an output limit may constrain the answer separately.
- Context Window vs Output Limit: the total context capacity is not the same as the maximum number of output tokens.
- Context vs Memory: context is active information for the current operation; memory may persist beyond the current operation.
- Context vs Model Parameters: context is supplied at runtime; parameters are learned values inside the trained model.
- Context vs Training Data: context is selected for the current request; training data was used earlier to train the model.
- Context vs Model Knowledge: information in context is explicitly provided now, while model knowledge is represented in learned patterns.
- Context Window vs Knowledge Database: a window is temporary active input space; a database is an external store of explicit records.
- Context Window vs External Memory: external memory can store information outside the active window and retrieve it later.
- Context Window vs RAG: the window is the destination working space; RAG is a retrieval-and-generation method that can add information to it.
- RAG vs Memory: RAG typically retrieves task-relevant external information; memory usually refers to information retained across interactions, although a memory system may use retrieval.
- Retrieval vs Context: retrieval finds information; context is the information made available to the model after selection.
- Retrieved Context vs Model Knowledge: retrieved context is supplied at runtime and does not necessarily change the model's learned knowledge.
- Context Window vs KV Cache: the context window is the logical available information; KV Cache is an implementation cache that helps process existing context efficiently during generation.
- KV Cache vs Context Window: KV Cache does not mean the model can accept unlimited new context; it stores intermediate representations for computation.
- KV Cache vs Memory: KV Cache is runtime computational state, not durable user memory.
- Token vs Context Window: a token is one processing unit; a context window is the capacity containing many tokens.
- Token vs Token Budget: a token is a unit; a token budget is a limit or allocation for units.
- Token Count vs Context Size: token count measures the content currently present; context size is the capacity available.
- Input Tokens vs Output Tokens: input tokens come from supplied context; output tokens are generated by the model.
- Context Size vs Maximum Answer Length: context size covers input plus output according to design; answer length may have a separate cap.
- Output Limit vs Context Limit: output limit applies to generated content; context limit applies to the total usable context.
- Long Conversation vs Long Context: a conversation can be long in history, but only the portion retained in the active context is visible to the model.
- Large Document vs Large Context Window: a large document may still need splitting or selective retrieval even when the model has a larger window.
- Split vs Summarize: splitting preserves separate detailed pieces; summarizing replaces detail with a shorter representation.
- Summarize vs Compact: summarization creates a shorter semantic description; compaction is a broader reduction of context that may use summarization or other methods.
- Remove vs Retrieve Again: removal takes information out of active context; re-retrieval finds it again when needed.
- Visible Context vs All Available Information: the model uses what is visible in the current window, not every piece of information that exists elsewhere.
- Conversation State vs Memory: conversation state describes the current interaction; memory may persist and be used across separate interactions.
- Current Request vs Conversation State: a request is one processing event; conversation state can include accumulated messages around that event.
- System Instructions vs User Messages: system instructions guide behavior at a higher instruction level; user messages state the user's task or question.
- Uploaded Content vs Retrieved Information: uploaded content comes directly from the user or task input; retrieved information is found from an external source.
- Tool Results vs Repository Files: tool results are generated by tool calls; repository files are pre-existing project artifacts that may be supplied as context.
- Coding Agent vs Model: a coding agent is a task-performing system that may use a model, files, tools, and history; the model is one component.
- Inference vs Training: inference uses the model and visible context to produce output; training changes learned model values.
- Inference vs Generation: inference is the broader runtime computation; generation is the production of new output within or as part of inference.
- Generation vs Output: generation is the process; output is the resulting content.
- Model Knowledge vs Current Information: model knowledge comes from training; current information must be supplied or retrieved at runtime.
- Model Knowledge vs Memory: learned model patterns are not the same as stored user-specific information.
- Context Injection vs Training: inserting information into context does not retrain or update the model.
- Context Compression vs Quantization: context compression reduces active content; quantization changes numerical representation of model values.
- Context Window vs Model Size: window size measures usable input/output context; model size often refers to parameters or weights.
- Context Capacity vs Model Capacity: context capacity is how much information fits now; model capacity is the model's ability to represent learned patterns.
- More Context vs Better Answer: adding more content does not guarantee a better answer if the content is irrelevant, conflicting, stale, or poorly organized.
- Larger Context Window vs Longer Answer: a larger window permits more total context; it does not necessarily increase the separately allowed answer length.
- Context Relevance vs Context Completeness: relevance asks whether the content is related; completeness asks whether the needed content is all present.
- Context Reliability vs Context Freshness: reliability concerns trustworthiness; freshness concerns how current the information is.
- Retrieved Context vs Ground Truth: retrieved context is evidence supplied to the model; it may still be incomplete or wrong.
- Memory Retrieval vs RAG Retrieval: both can bring information into context, but memory usually concerns retained interaction information while RAG commonly concerns external knowledge retrieval.
- Context Overflow vs Hallucination: overflow is a capacity problem; hallucination is an incorrect or unsupported output problem, though overflow can contribute to it.
- Context Loss vs Forgetting in Training: context loss means information is no longer active in the current request; training forgetting concerns changes to learned model behavior.
- Context Window vs Conversation Storage: the window is what the model can use now; storage may contain a much larger history that is not currently visible.
- Context Usage vs Cost: using more context can affect cost, but context usage and monetary cost are not identical metrics.
- Context Usage vs Latency: more context may increase processing time, but token usage and latency are different measurements.
- Context Limit vs Provider Limit: a model may have a nominal limit while a specific provider or API imposes a different effective limit.
- Context Length vs Document Length: document length is the size of a source document; context length is the amount actually supplied to the model.
- Context Window vs Prompt: the prompt is supplied instruction/content; the context window is the capacity that contains prompt and other context.
- Prompt vs System Instruction: a prompt may be broad input/context; a system instruction is a particular high-priority guidance source.
- Prompt Context vs Conversation History: prompt context can include any supplied background; conversation history is specifically earlier conversation messages.
- Existing Context vs KV Cache: existing context is logical information already present; KV Cache is cached computation derived from it.
- Compaction vs Caching: compaction changes/reduces active content; caching stores computation or content for reuse.
- Selective Retrieval vs Truncation: selective retrieval chooses relevant content before insertion; truncation removes content to satisfy a limit, often without semantic selection.
- Summary vs Original Document: a summary is a shorter representation and may omit details; the original contains the full source content.
- Summary vs Memory: a summary is a representation of content; memory is the broader storage/retrieval capability.
- Context Window vs Attention Span: a context window is the available token range; attention behavior determines how the model uses information within that range.
- Context Window vs Context Awareness: the window is a capacity/contents concept; context awareness is the ability to use surrounding information.
- Context State vs Persistent State: context state can be request-scoped; persistent state survives beyond a single operation.
- Tokenization vs Chunking: tokenization creates model units; chunking divides documents into larger retrieval/processing pieces.
- Tokenization vs Embedding: tokenization represents text as token IDs; embedding maps tokens or text into numerical vectors.
- Retrieval vs Reranking: retrieval finds candidate information; reranking orders candidates by relevance.
- Retrieval vs Generation: retrieval obtains existing information; generation produces new output.
- Output Token vs Token Probability: an output token is generated content; a probability is a score or distribution used to choose a token.
- Context Window vs API Request Payload: the payload is what is sent over an interface; the effective context includes how the model counts and processes that payload plus generated output.
- Input Budget vs Output Budget: input budget reserves capacity for supplied content; output budget reserves capacity for generated content.
- Current Operation vs Entire Session: a current operation is one model run; a session may contain multiple runs and stored history.
