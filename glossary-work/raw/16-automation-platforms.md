## Do Not Confuse Candidates

- automation platform vs workflow: an automation platform is the software environment; a workflow is one configured sequence inside it.
- automation vs automation platform: automation is the behavior or outcome; an automation platform is the tool that builds and runs it.
- trigger vs action: a trigger starts a workflow; an action is performed after the workflow starts.
- condition vs trigger: a trigger begins execution; a condition decides whether an already-running workflow proceeds.
- action vs notification: an action can change data or create work; a notification specifically informs a person or system.
- app connection vs API: an app connection is a configured relationship in the platform; an API is an interface that may implement that relationship.
- data vs data transformation: data is the information; transformation changes its shape or content.
- workflow vs process: a workflow is an explicit sequence that can be modeled and executed; a business process is the broader organizational activity.
- manual handoff vs notification: a notification informs someone; a manual handoff transfers responsibility or work.
- node-based vs visual: node-based describes a graph of nodes; visual is the broader idea of designing through a visual interface.
- low-code vs no-code: low-code reduces hand-written code but may still require it; no-code aims to require none.
- self-hosted vs SaaS: self-hosted runs in infrastructure controlled by the user; SaaS is delivered as an online service managed by the provider.
- n8n vs Zapier vs Make vs Microsoft Power Automate: these are separate platforms with different styles, audiences, integrations, and deployment models.
- Microsoft Power Automate vs Microsoft 365: Power Automate is the automation service; Microsoft 365 is the broader productivity suite it can integrate with.
- Dynamics vs CRM: Dynamics is a named Microsoft business-application family; CRM is the broader category of customer-management systems.
- Slack vs Teams: both can receive notifications, but they are different collaboration products.
- API orchestration vs data transformation: orchestration coordinates calls and steps; transformation changes the data passed between them.
- branching vs condition: a condition evaluates a rule; branching uses that result to send execution down different paths.
- automation vs agent: automation usually follows predefined logic; an agent can dynamically choose next steps based on context.
- predefined vs adaptive: predefined behavior is configured in advance; adaptive behavior changes with context or circumstances.
- agent step vs full agent: an agent step is one component inside a workflow; a full agent may control a broader task loop.
- AI step vs AI workflow platform: an AI step is one workflow operation; an AI workflow platform is the surrounding product category.
- AI workflow platform vs automation platform: the page presents AI workflow platforms as centered on prompts, models, RAG, and agents, while automation platforms center on business apps and triggers; capabilities increasingly overlap.
- optional AI vs AI-native: optional AI can be added to a general workflow; AI-native means the application workflow is designed around AI.
- classification vs decision support: classification assigns a category; decision support gives information or suggestions to help a person decide.
- extraction vs summarization: extraction pulls selected facts; summarization condenses the overall content.
- generation vs extraction: generation creates new output; extraction retrieves information already present in the input.
- notification vs report generation: a notification is a message intended to inform; a report is a more structured presentation of information.
- CRM update vs CRM task: an update changes a record; a task creates work to be followed up.
- data synchronization vs data transformation: synchronization keeps systems aligned; transformation converts data into another form.
- approval workflow vs condition: an approval workflow involves an authorization process; a condition is a rule that can be evaluated automatically.
- self-hosting vs technical flexibility: self-hosting is a deployment model; technical flexibility is the broader ability to customize.
- fit signal vs single winner: a fit signal describes a match for a need; it does not prove one platform is best in every situation.
- workflow platform vs agent framework: a workflow platform designs and runs business processes; an agent framework is a developer layer for building agent systems.
- application connection vs integration: a connection may be one link; integration may include data mapping, rules, validation, controls, and ownership.
- AI classification vs human decision: AI can classify or support a decision; it does not automatically mean a human approval is unnecessary.
- run automatically vs run unattended: automatic execution reduces manual starts, but a safe production workflow may still require review or approval.
