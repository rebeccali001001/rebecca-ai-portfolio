## Do Not Confuse Candidates

- **Multi-Agent System vs one agent with many tools**：多智能体系统有多个相互交互的角色或循环；一个带很多工具的智能体仍然只有一个决策者。
- **Multi-Agent System vs multiple LLM calls**：多智能体系统协调不同角色或智能体；多次 LLM 调用可能只是没有智能体交互的顺序序列。
- **Multi-Agent System vs more agents**：多智能体结构是架构特征；单纯增加智能体数量不保证更好性能。
- **agent vs agent role**：agent 是参与工作的实体；role 是这个实体承担的职责，两者不是同一层级。
- **agent vs tool**：agent 负责参与任务、协作或决策；tool 是某个 agent 可以使用的能力。
- **multiple agents vs multiple roles**：多个角色可以由多个智能体承担，也可能只是一个系统中的抽象分工；页面将它们作为相关但可区分的表达。
- **coordinator vs central coordinator**：coordinator 可以是一个角色或组件；central coordinator 明确表示由一个中心点连接工作。
- **centralized coordination vs decentralized coordination**：前者依赖一个中央协调者；后者不依赖单一中心。
- **coordination vs collaboration**：coordination 侧重组织和连接；collaboration 侧重共同完成工作。
- **communication vs coordination**：communication 是信息交换；coordination 是利用信息组织行动。
- **shared state vs shared task**：shared state 是共享的信息状态；shared task 是共同要完成的任务。
- **messages vs artifacts**：messages 通常是传递的信息；artifacts 是可交接的工作成果。
- **state vs result**：state 表示当前工作信息；result 是某个阶段或最终产生的结果。
- **input vs output**：input 是交给系统的请求或功能请求；output 是系统返回的成果。
- **result vs deliverable**：result 可以是中间结果；deliverable 强调可交付的最终工作成果。
- **review vs evaluation**：review 是检查某个具体结果；evaluation 更宽泛地判断系统性能。
- **reviewer vs coordinator**：reviewer 检查结果；coordinator 连接或组织工作。
- **review role vs writing role**：review role 检查草稿或结果；writing role 生成草稿。
- **researcher vs writer**：researcher 找信息；writer 把信息写成草稿。
- **checked draft vs proposed change**：checked draft 是研究写作例子的输出；proposed change 是软件开发例子的输出。
- **sources vs test evidence**：sources 支持报告内容；test evidence 支持软件改动。
- **task vs subtask**：task 是整体工作；subtask 是拆分出来的一部分。
- **divide vs delegate**：divide 是把整体拆成几部分；delegate 是把某部分交给某个智能体。
- **parallel work vs sequence**：parallel work 同时进行；sequence 按顺序进行。
- **coordination cost vs latency**：coordination cost 是广义额外代价；latency 是时间上的延迟。
- **errors vs performance**：errors 是错误结果或故障；performance 是整体表现，可能受错误影响但不等同于错误。
- **capability vs role**：capability 是能做什么；role 是在团队中负责什么。
- **goal vs output**：goal 是希望达成的目标；output 是实际返回的产出。
- **goal vs task**：goal 是期望结果；task 是为达成结果而要完成的工作。
- **workflow vs process step**：workflow 是完整流程；process step 是其中一个步骤。
- **Goal / Assign / Work / Exchange / Review vs generic words**：这些既是普通英文词，也在本页作为带编号的五个流程节点使用。
- **LLM vs agent**：LLM 是模型调用对象；agent 是参与任务、角色协作和工作循环的系统实体。
- **LLM call vs agent interaction**：LLM call 只是一次模型调用；agent interaction 要求角色或智能体之间发生交互。
- **tool calling vs multi-agent system**：工具调用是使用工具的机制；多智能体系统是多个智能体协作的系统结构。
- **planning vs multi-agent planning**：页面只在软件开发例子中提到 planning；并没有定义多个智能体如何共同规划。
- **Memory & State vs shared state**：Memory & State 是相关概念链接；shared state 是本页正文中的协调方式。
- **Human in the Loop vs decentralized coordination**：前者强调人的参与；后者强调智能体之间是否有中心协调者。
- **project team analogy vs literal human team**：项目团队只是帮助理解的类比，不表示页面要求使用真实人类团队。
- **AI / System vs individual agent**：AI / System 是例子中的整体工作安排；individual agent 是其中一个工作角色。
- **system vs multi-agent system**：system 是通用词；multi-agent system 明确要求多个相互作用的 agent。
- **specialized role vs specialized model**：specialized role 是工作分工；页面没有声称每个角色必须使用不同模型。
- **decentralized coordination vs no coordination**：去中心化仍然有协调；没有中央协调者不等于完全没有协调。
- **more agents vs better performance**：数量增加可能带来 coordination cost、errors 和 latency；性能还取决于 task fit、communication 和 evaluation。
- **one or more goals vs one shared goal**：页面允许一个或多个目标，不应擅自假设所有智能体只有一个共同目标。
- **check the result vs guarantee correctness**：检查能提高可信度，但页面没有声称复核自动保证结果正确。
- **video explainer vs topic explanation**：视频讲解是可选媒体资源；页面正文本身已经提供文字讲解。
- **MCP vs multi-agent system**：MCP 只出现在上级主题名称中；本页没有定义 MCP 协议、服务器或客户端。
