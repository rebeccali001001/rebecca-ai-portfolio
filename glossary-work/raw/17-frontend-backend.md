## Do Not Confuse Candidates

| Candidate A | Candidate B | Difference to preserve |
|---|---|---|
| frontend | backend | Frontend is the user-facing layer; backend performs hidden logic, data, and service work. |
| frontend | frontend framework | Frontend is the product layer/experience; a frontend framework is a development structure used to build it. |
| backend | database | Backend is the broader processing and service layer; a database is one backend component for storing data. |
| backend | server | Backend describes application-side work; server can mean the machine or runtime that hosts that work. |
| authentication | permission | Authentication checks who someone is; permission determines what that person may do. |
| permission | authorization | The page uses permission but does not define authorization; authorization is the broader access-control concept often associated with permission checking. |
| request | response | A request asks for work; a response carries the result back. |
| request | user action | The user's action starts the flow; the request is the message the frontend sends after or because of that action. |
| response | displayed result | A response is returned by the backend; a displayed result is the frontend-rendered presentation of it. |
| business logic | database | Business logic decides how a product should behave; a database stores information. |
| API | external API | API is the general communication interface concept; external API is an API owned or provided outside the product. |
| external API | backend | An external API is something the backend may call; it is not automatically part of the product's own backend. |
| AI | AI model | AI is the broad field/capability; an AI model is a concrete model used to provide that capability. |
| AI model | backend | The model provides AI processing; the backend coordinates the call and connects it to product logic and data. |
| framework | model | A framework organizes software construction; a model supplies AI capability. |
| frontend technology | frontend framework | HTML/CSS/JavaScript and named frameworks are examples in the page, but “technology” is broader than “framework.” |
| website | frontend | A website is one kind of product/interface delivery; frontend is the layer concept that also covers mobile interfaces and other surfaces. |
| dashboard | backend | A dashboard is a visible frontend screen; backend logic and data may support it but are not the dashboard itself. |
| form | input | A form is the interface control; input is the information entered through it. |
| account | authentication | An account is stored user information; authentication is the process of verifying identity. |
| account | permission | An account represents a user; permission controls what that user is allowed to do. |
| service | API | A service performs a capability; an API is the interface through which software can request that capability. |
| full stack | full-stack product | Full stack describes coverage across layers; a full-stack product is one product whose experience and supporting logic are connected. |
| full stack | separate product kind | Full stack is a scope/coverage description, not a separate product category. |
| user experience | user interface | User experience is the broader experience of using a product; user interface is the visible interaction surface. |
| application logic | business logic | Application logic is broad processing behavior; business logic is the product-specific rules within it. |
| retrieve document | generate summary | Retrieval finds/loads the source document; generation produces the summary from processed content. |
| frontend sends request | backend returns result | These are different stages and directions in the flow. |
| typical data | typical technologies | Data describes information handled; technologies describe tools or languages used to implement a layer. |

## Notes

- The source page is an introductory, architecture-level explanation rather than a detailed programming lesson.
- The page explicitly says that detailed frontend technologies belong in Module 19; the named technologies are retained as candidates because they appear in the page.
- The page contains no explicit quantitative metrics, benchmarks, thresholds, or performance indicators. No metric candidates were invented for the raw source-derived table.
- The table intentionally keeps capitalization (`Frontend`, `Backend`, `REQUEST`, `RESPONSE`), casing (`Full Stack`, `full stack`, `full-stack`), singular/plural forms, and repeated or near-repeated wording instead of consolidating them.
- “Backend + AI” in the example is a flow label, not a claim that AI is identical to backend; the backend invokes or coordinates the AI capability.
- The page's core architecture flow is: user opens the product and acts → frontend presents/captures the action → frontend sends a request → backend applies logic/data/services and may call AI or external APIs → backend returns a response/result → frontend displays it to the user.
- The page uses “authentication” and “permission” as backend examples but does not teach the distinction between authentication and authorization; that distinction is listed under Potential Missing Concepts and Do Not Confuse Candidates.
