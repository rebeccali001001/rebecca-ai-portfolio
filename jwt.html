MODULE 06 · AUTHENTICATION & SECURITY

JWT

A JSON Web Token is a compact, signed value that carries claims between a client and a server.

01 · What is it?

A JWT is a compact token whose claims are encoded as JSON and whose signature lets a server detect tampering.

A JWT commonly contains a header, a payload, and a signature. The payload is readable by anyone who receives the token, so it should not be treated as secret storage.

02 · Think of it like...

Think of a JWT like a signed pass that carries its own visible details.

A guard can read the pass and check its signature before accepting it. The signature supports trust in the contents, while the guard still checks whether the pass is expired and valid for this door.

Claims→Signed JWT→Server verifies→Access decision→Protected resource

03 · What does it do?

A JWT gives a server a portable way to carry identity or authorization claims across requests.

Carry Claims

Represent facts such as a subject, issuer, audience, or expiration time.

Detect Changes

Let the verifier reject a token whose signed contents were altered.

Support Stateless Checks

Allow a service to verify a token without looking up a session for every request.

Limit Validity

Use expiration and audience claims to narrow when and where the token is accepted.

04 · Where is it used?

JWTs are used when services need a portable, verifiable representation of a login or delegated access decision.

Web ApplicationsBrowser to API

An API validates a token sent with a protected request.

Mobile AppsApp sessions

An app keeps an access token and presents it to a backend.

Service APIsService to service

A service verifies the issuer, audience, and signature of an incoming token.

Identity SystemsFederated access

An identity provider issues claims that another service can verify.

05 · Example

Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c2VyLTEyMyIsImV4cCI6MTg5MzQ1NjAwMH0.signature

The client sends the token in a request header. The API verifies the signature and checks claims such as expiration and audience before serving the request.

This token is illustrative. A JWT is encoded, not encrypted; use encryption or another protected channel when claims must remain confidential.

06 · How it connects

Login request→Identity check→JWT issued→Bearer request→API verifies

Authentication establishes who the caller is. Authorization decides what that caller may do. JWT validation is one part of that larger security flow.

07 · Do Not Confuse

JWT

A token format for carrying claims, often with a signature.

Session

Server-managed state that associates a session identifier with stored data.

Encryption

A method for keeping information unreadable without the right key; signing a JWT does not provide that confidentiality.

A valid signature does not automatically mean the request should be allowed. The server must still apply expiration, audience, scope, and permission rules.

09 · What to Remember

A JWT is a signed, portable container for claims.

It can help a server verify token contents across requests, but it does not replace authorization checks or secure secret handling.

Core Flow:
Issue JWT → Send JWT → Verify signature and claims → Apply permissions
