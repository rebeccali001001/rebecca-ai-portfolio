One-to-Many

A one-to-many relationship means one record in one table can be associated with many records in another table.

01 · What is it?

One parent record can connect to many child records, while each child record points back to one parent.

For example, one customer can place many orders. The relationship is stored with a foreign key in the table on the “many” side.

02 · Think of it like...

Think of one customer as a folder that can hold many order receipts.

The customer is the single parent. Each order is a separate child record, but every order keeps the customer’s ID so the system knows which folder it belongs to.

03 · What does it do?

A one-to-many relationship keeps related data connected without repeating the parent’s full details in every child row.

Connect Records

Use a foreign key to connect each child to its parent.

Keep Data Organized

Store customers, orders, or other entities in separate tables.

Query Related Data

Find all child records that belong to one parent.

04 · Where is it used?

One-to-many relationships appear wherever one entity can own, create, or contain multiple related entities.

Customers → Orders

One customer can place many orders.

Authors → Posts

One author can publish many posts.

Teams → Members

One team can include many members.

Departments → Employees

One department can contain many employees.

Invoices → Line Items

One invoice can list many purchased items.

Projects → Tasks

One project can contain many tasks.

05 · Example

CREATE TABLE orders (
  id INTEGER PRIMARY KEY,
  customer_id INTEGER NOT NULL,
  total DECIMAL(10, 2),
  FOREIGN KEY (customer_id)
    REFERENCES customers(id)
);

SELECT *
FROM orders
WHERE customer_id = 42;

The orders.customer_id foreign key points to customers.id. Customer 42 can therefore have many rows in orders, and the query returns every order for that customer.

The foreign key lives on the many side: every order stores the ID of its one customer.

A primary key identifies the parent; matching foreign-key values gather the related child records.

07 · Do Not Confuse

One-to-Many

One parent record can relate to many child records.

Many-to-Many

Many records on both sides relate to each other, usually through a join table.

One-to-One

One record matches at most one record in the related table.

One-to-many describes the relationship’s cardinality; it does not mean one table is physically nested inside another.

09 · What to Remember

In a one-to-many relationship, one parent record connects to many child records. Put the parent’s primary key into the child table as a foreign key.
