Observability

Observability helps developers see what is happening inside an AI system—and understand why it is slow, failing, expensive, or producing a weak result.

The goal is not to collect data for its own sake. The goal is to turn a confusing production behavior into an explainable path from request to result.

Logs · Metrics · Traces

These are the three core data shapes that help explain system behavior.

LogsEvent records: what happened, when, and with which request.
MetricsNumbers over time: latency, error rate, token usage, and cost.
TracesOne connected request path across retrieval, models, tools, and agent steps.

What an AI system can expose

A useful AI trace carries more than a server status code. It connects the system's behavior to the AI-specific work that produced the result.

PromptWhat instructions were sent?
Context SizeHow much information was included?
Token UsageHow many input and output tokens were used?
Model CallWhich model request ran?
LatencyHow long did each step take?
RetrievalWhat information was found?
Tool CallsWhich external actions ran?
Agent StepsWhat did the agent decide and do?
Errors · CostWhat failed, and what did the run consume?

Complete Trace Example

A trace makes one user request inspectable from start to finish.

User Request—request received
↓ RAG Search0.4sretrieval
↓ Prompt Build0.1scontext assembled
↓ Model Call5.2sgeneration
↓ Tool Call8.1sexternal action
↓ Model Call3.4sfinal synthesis
↓ Final Answer—response returned
Total = 17.2s

What did observability reveal? The real bottleneck is the Tool Call at 8.1s—not the model. Without a trace, the whole request might simply look “slow.”

Monitoring vs Observability

MONITORING

Checks known signals and asks: “Is something outside the expected range?” It is useful for dashboards, thresholds, and alerts.

OBSERVABILITY

Uses logs, metrics, and traces to ask: “Why did this happen?” It helps investigate unfamiliar problems.

Simple difference: monitoring tells you that there may be a problem; observability helps you understand the problem.
