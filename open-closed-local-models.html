Open vs Closed / Local Models

AI models differ not only in capability, but also in how their weights are distributed, where they can run, and who controls the infrastructure.

Main Mental Model

Two axes, two different questions

Access describes who can obtain or use the model. Location describes where inference happens. A model can be open-weight and hosted in the cloud, or closed and available through a cloud API.

Open-weight Models

Weights are available under stated terms

Open-weight means model weights are available under a stated license or terms of use. They can be obtained and then used with compatible software and hardware.

Possible runtimes include Ollama, vLLM, and other compatible serving stacks. Open-weight ≠ open-source, and open-weight ≠ automatically local-friendly.

Open-source vs Open-weight

Related terms, different scope

OPEN-WEIGHT

Model weights are available under a stated license.

OPEN-SOURCE

A broader concept involving source availability and licensing rights. AI industry usage varies; inspect the actual license.

What Is a Local Model?

Local describes location, not authorship

A local model runs inference on hardware you control: a laptop, desktop, workstation, or local server. Local does not describe who created the model.

LOCAL-CAPABLE IS A PRACTICAL TEST

Open weights + supported format + compatible runtime + enough memory + enough compute → practical local model.

Why Hardware Matters

Model file size is not total runtime memory

A model file is only one part of the memory budget. Context length, runtime, format, concurrency, and hardware all change the result.

When Would Someone Choose Each?

Match the strategy to the constraint

I want the easiest setup

→ Cloud API

I need high-end models without buying hardware

→ Cloud

I need local control or offline use

→ Local-capable open-weight model

I need to customize infrastructure

→ Self-hosted / open-weight option

I have limited hardware

→ Smaller or quantized models, or cloud
